# 04. 프롬프트 기본기 — 3S 원칙과 상황별 템플릿

## 학습 목표

- 좋은 프롬프트의 **3S 원칙** (Simple · Specific · Structured) 체득
- BAD vs GOOD 프롬프트 5가지 비교로 감각 익히기
- 상황별 프롬프트 템플릿 5개를 복사해서 바로 쓸 수 있음
- **한국어 프롬프트의 함정**을 알고 피하기

**예상 소요**: 20분 (실습 포함 30분)

---

## 4.1 왜 프롬프트가 중요한가

같은 도구를 써도 **결과 품질이 3배 이상 차이**납니다. 이 차이는 오직 프롬프트에서 옵니다.

### 극단적 비교

**나쁜 프롬프트**
```
마케팅 자료 만들어줘
```
→ 어떤 제품인지, 어떤 형식인지, 누구를 위한지 아무것도 없음 → 뻔한 초안.

**좋은 프롬프트**
```
20대 여성 대상 스마트워치 "X" 인스타그램 스토리 카피 3개 만들어줘.

- 각 카피는 30자 이내
- 이모지 1개씩 포함
- 첫 카피는 문제 제기, 두 번째는 해결책, 세 번째는 행동 유도
- 톤: 친근하고 힙하게
```
→ 붙여넣어서 바로 쓸 수 있는 3개.

---

## 4.2 3S 원칙

프롬프트가 갖춰야 할 3가지 특성입니다.

| 원칙 | 뜻 | 실전 적용 |
|------|-----|-----------|
| **Simple** | 간결하게 | 불필요한 인사·수식어 제거, 요청은 명령형으로 |
| **Specific** | 구체적으로 | 대상·형식·톤·길이·예시를 명시 |
| **Structured** | 구조적으로 | 목록·표·번호로 요구사항 정리 |

### Simple — 간결하게

**❌ BAD**
```
안녕하세요 Copilot 저는 지금 조금 어려움을 겪고 있는데
혹시 시간이 되신다면 저희 회사 신제품 관련 마케팅 문구를
좀 부탁드릴 수 있을까요 감사합니다
```

**✅ GOOD**
```
신제품 스마트워치 X의 인스타 광고 카피 3개 작성.
20대 여성 타겟, 각 30자 이내.
```

- AI는 예의를 필요로 하지 않습니다. **명령형으로 짧게.**

### Specific — 구체적으로

**❌ BAD**
```
이메일 좀 만들어줘
```

**✅ GOOD**
```
CS 팀 대응 이메일 템플릿 작성:

- 상황: 배송 지연 사과
- 톤: 정중하지만 과하지 않게
- 포함: 지연 사유, 예상 도착일, 보상책(10% 할인 쿠폰), 담당자 연락처
- 길이: 5문장 이내
- 서명: "홍길동 / 고객경험팀"
```

- **누구에게, 무엇을, 어떤 형식으로, 얼마 길이로** 4가지는 최소한 명시.

### Structured — 구조적으로

**❌ BAD (한 덩어리)**
```
회의록을 만들려는데 참석자는 김철수 이영희 박민수이고
안건은 신제품 출시 일정 마케팅 예산 채용 계획이고
각각의 결정사항이랑 액션 아이템도 포함해줘
```

**✅ GOOD (구조화)**
```
회의록 Markdown 템플릿 작성.

## 회의 정보
- 일시: 2026-07-20 14:00
- 참석자: 김철수, 이영희, 박민수

## 안건 (각각 다음 4항목 포함)
1. 신제품 출시 일정
2. 마케팅 예산
3. 채용 계획

각 안건별 항목:
- 논의 내용
- 결정 사항
- 액션 아이템 (담당자 / 마감일)
- 다음 회의 안건
```

- 목록·번호·계층으로 요구사항을 분리 → AI가 놓치지 않음.

## 4.3 BAD vs GOOD 5선

### 1) 문서 작성

| 종류 | 프롬프트 |
|------|----------|
| ❌ | "보고서 목차 만들어줘" |
| ✅ | "2026년 상반기 마케팅 성과 보고서 목차를 Markdown으로 작성. 대상: 임원 발표용. 섹션 5개: (1) 요약(1페이지), (2) KPI 현황, (3) 캠페인별 성과, (4) 인사이트, (5) 하반기 전략. 각 섹션 아래 하위 항목 2~3개." |

### 2) 엑셀 수식

| 종류 | 프롬프트 |
|------|----------|
| ❌ | "합계 구하는 수식" |
| ✅ | "엑셀 A1:A100 범위에서 값이 100 이상인 셀의 개수와 합계를 각각 다른 셀에 구하는 수식 2개. 함수는 COUNTIF, SUMIF 사용." |

### 3) SQL

| 종류 | 프롬프트 |
|------|----------|
| ❌ | "매출 뽑는 쿼리" |
| ✅ | "테이블 orders(id, customer_id, amount, created_at)에서 2026년 6월 매출을 고객별로 집계. 매출액 상위 10명만. amount는 원 단위 정수, 결과는 이름·매출액·주문건수 3열. PostgreSQL 문법." |

### 4) 이메일

| 종류 | 프롬프트 |
|------|----------|
| ❌ | "고객 응대 메일" |
| ✅ | "환불 요청 거절 이메일 초안. 사유: 사용 흔적으로 재판매 불가. 톤: 정중하지만 단호. 5문장 이내. 대체 제안(교환 or 크레딧 100%)도 포함. 서명 '{{담당자명}} / 고객경험팀'." |

### 5) 스크립트

| 종류 | 프롬프트 |
|------|----------|
| ❌ | "폴더 정리 스크립트" |
| ✅ | "Windows PowerShell 스크립트: `C:\Downloads` 폴더의 파일들을 확장자별 하위 폴더(images, docs, videos, others)로 이동. 이미지=jpg/png/gif, 문서=pdf/docx/xlsx, 영상=mp4/mov, 나머지=others. 스크립트 상단에 사용법 주석 포함." |

**차이의 공통점**: 좋은 프롬프트는 **대상, 형식, 도구/문법, 길이, 예외 처리**를 다 담습니다.

## 4.4 상황별 프롬프트 템플릿 (복사해서 쓰기)

### 템플릿 1. 문서 초안 생성

```
[문서 종류] 작성.

목적: [무엇을 위해]
독자: [누가 읽나]
톤/스타일: [예: 정중, 친근, 기술적]
길이: [예: A4 1페이지, 500자 이내]

구조:
1. [섹션명] — [내용 설명]
2. [섹션명] — [내용 설명]
...

포함해야 할 것:
- [필수 항목1]
- [필수 항목2]

제외할 것:
- [피할 것]
```

### 템플릿 2. 데이터 변환/정제

```
데이터 [변환/정제/집계] 작업.

입력 데이터 형식: [예: CSV, JSON, 엑셀]
현재 형태 예시:
[샘플 3~5줄 붙여넣기]

원하는 결과 형태:
[샘플 3~5줄 붙여넣기]

사용 도구: [엑셀 수식 / SQL / Python / PowerShell 중 택1]
```

### 템플릿 3. 반복 업무 자동화 스크립트

```
[언어] 스크립트 작성.

목적: [무엇을 자동화]
입력: [파일 위치, 형식]
동작:
1. [단계]
2. [단계]
3. [단계]

출력: [결과 파일/폴더/형식]
예외 처리:
- [상황1] → [처리]
- [상황2] → [처리]

주석: 스크립트 상단에 사용법 3줄 설명 포함.
```

### 템플릿 4. 요약 / 재작성

```
아래 [원문/이메일/회의록]을 [형식]으로 요약.

목적: [예: 임원 보고용, 슬랙 공유용]
길이: [예: 3문장, 5개 불릿]
톤: [예: 사실 위주, 감정 배제]

강조할 것: [핵심 키워드]

[--- 원문 시작 ---]
(여기에 원문 붙여넣기)
[--- 원문 끝 ---]
```

### 템플릿 5. 검토 / 개선 요청

```
아래 [문서/코드/이메일]을 검토하고 개선안 제시.

검토 관점:
1. [예: 논리 흐름]
2. [예: 존댓말/오탈자]
3. [예: 톤이 회사 브랜드에 맞는가]

원하는 결과 형식:
- 발견한 문제 목록
- 각 문제에 대한 개선안
- 개선한 최종 버전

[--- 대상 ---]
(붙여넣기)
```

## 4.5 한국어 프롬프트의 함정 3가지

### 함정 1. 문법 요소를 한국어로 요청

**❌ BAD**
```
사용자 이름을 저장하는 변수 만들어줘
```
→ Copilot이 변수명을 `사용자이름` 같이 한글로 만들 수도 있음.

**✅ GOOD**
```
사용자 이름을 저장하는 변수 만들어줘. 변수명은 영어 camelCase (예: userName).
```

**원칙**: **문법 요소(변수명, 함수명, 컬럼명, 파일명)는 영어로 유지**하도록 명시.

### 함정 2. 존댓말 남발로 프롬프트가 길어짐

**❌ BAD**
```
혹시 괜찮으시다면 이 부분을 조금 더 자세히 설명해주실 수 있을까요...
```

**✅ GOOD**
```
이 부분을 초등학생도 이해할 수준으로 설명.
```

- **명령형이 더 정확**합니다. 존댓말·완곡어법은 오히려 애매함 유발.

### 함정 3. "알아서 해줘"

**❌ BAD**
```
알아서 잘 만들어줘
```
→ AI의 "알아서"는 대체로 평균적/뻔한 결과.

**✅ GOOD**
```
[구체적 기준 A]와 [B]를 만족하도록 만들어줘. 특히 [C] 관점에서 뛰어나야 함.
```

- **"알아서"라고 하면 알아서 실망**합니다. 기준을 여러분이 정해주세요.

## 4.6 프롬프트 개선 순환 (Iterate)

첫 결과가 마음에 안 들 때, 처음부터 다시 쓰지 말고 **한 문장 추가**로 개선합니다.

```
1차 프롬프트 → 결과 확인

2차: "위 결과에서 [A]를 [B]로 바꿔줘"

3차: "위 결과에 [C]도 추가"

4차: "이걸 [D] 형식으로 다시 정리"
```

Chat 사이드바에서 대화가 이어지므로, **점진적으로 원하는 결과에 수렴**시킬 수 있습니다.

## 실습

### 실습 1. BAD → GOOD 개선하기

다음 3개의 BAD 프롬프트를 GOOD으로 개선해서 종이/메모장에 적어보세요.

1. `보고서 만들어줘`
2. `이 텍스트 좀 잘 정리해줘`
3. `엑셀에서 뭐 좀 계산하는 함수 알려줘`

**팁**: 3S 원칙(Simple·Specific·Structured)과 5W(누가/무엇을/어디에/왜/어떻게)를 체크리스트처럼 사용.

### 실습 2. 템플릿 실전 적용

앞의 **템플릿 1 (문서 초안 생성)**을 사용해서, 여러분 팀의 **주간 회고 문서 템플릿**을 만들어달라고 Chat에 요청해보세요.

**힌트**: 목적=팀 회고, 독자=팀원, 톤=솔직함, 길이=1페이지, 구조=Keep/Problem/Try 3섹션.

### 실습 3. 개선 순환 실습

Chat 사이드바에서 다음 흐름으로 5회 이상 주고받기:

```
1차: "신입사원 온보딩 체크리스트 작성"
   → 결과 확인

2차: "각 항목마다 담당자와 소요 시간 열 추가"
   → 결과 확인

3차: "1주차/2주차/3주차/4주차 4개 그룹으로 나눠줘"
   → 결과 확인

4차: "표를 Markdown으로 다시 정리"

5차: "각 항목에 관련 담당팀도 표시 (인사팀/개발팀/일반)"
```

→ 5차 결과가 처음보다 얼마나 실무에 가까운지 눈으로 확인.

---

## 핵심 포인트

1. **3S 원칙**: Simple(간결) · Specific(구체) · Structured(구조)
2. **4대 명시**: 대상 · 형식 · 길이 · 톤 — 이 4개는 매번 포함
3. **템플릿 5개**를 나만의 스니펫으로 저장해두고 반복 사용
4. **한글 함정 3가지**: 영어 용어 유지 명시 / 명령형 사용 / "알아서" 금지
5. **한 번에 완벽 X, 개선 순환 O** — 짧게 여러 번이 더 빠름
