# 01. PM 업무에서 Copilot이 바꾸는 것

## 학습 목표

- PM의 하루 업무 중 Copilot이 직접 도움이 되는 태스크 15가지를 파악한다
- 태스크별 예상 시간 절감을 현실적으로 이해한다
- Before/After 비교 3가지를 직접 확인하고 "이건 나도 쓸 수 있겠다"는 감각을 잡는다

**예상 소요**: 40분 (이론 15분 + 실습 25분)

---

## 1.1 PM의 하루 업무 분해

PM은 하루에 얼마나 많은 문서를 씁니까? 실제로 따져보면 생각보다 훨씬 많습니다.

일반적인 PM의 하루를 시간대별로 분해하면 이렇습니다:

```
09:00  스탠드업 회의 (참석 + 회의록 작성)
09:30  JIRA 티켓 업데이트 (어제 회의 결과 반영)
10:00  PRD 작성 or 개발팀 질문 응대
12:00  점심
13:00  이해관계자 보고 자료 준비
14:00  디자인/개발 리뷰 미팅
15:00  사용자 인터뷰 정리 or 데이터 분석 요청
16:00  다음 스프린트 백로그 정리
17:00  이메일/슬랙 처리, 리포트 작성
```

이 중에서 순수 **문서 작성 + 정보 정리 + 커뮤니케이션**이 차지하는 비율은 보통 50~60%입니다.
Copilot은 바로 이 영역을 겨냥합니다.

---

## 1.2 Copilot이 보조/대체 가능한 15가지 태스크

아래 표는 실제 PM 업무를 분석해서 Copilot 활용 가능성과 예상 시간 절감을 정리한 것입니다.

| # | 태스크 | 기존 소요 시간 | Copilot 사용 후 | 절감율 |
|---|--------|--------------|----------------|--------|
| 1 | PRD 초안 작성 (신기능 1개) | 2~3시간 | 40~60분 | 65% |
| 2 | 사용자 스토리 20개 작성 | 1~2시간 | 15~20분 | 80% |
| 3 | 회의록 구조화 | 30~45분 | 5~10분 | 80% |
| 4 | 회의록 → JIRA 티켓 변환 | 45~60분 | 10~15분 | 75% |
| 5 | 임원 보고용 1페이지 요약 | 1~1.5시간 | 20~30분 | 67% |
| 6 | 요구사항 명세서 정리 | 1~2시간 | 30~40분 | 70% |
| 7 | 엣지케이스 발굴 | 1시간 | 15분 | 75% |
| 8 | API 명세 이해 (Swagger 읽기) | 1~2시간 | 20분 | 80% |
| 9 | 개발자 PR 내용 파악 | 30~60분 | 10분 | 75% |
| 10 | 릴리즈 노트 작성 | 30~45분 | 10분 | 75% |
| 11 | 이해관계자 이메일 초안 | 20~30분 | 5~8분 | 70% |
| 12 | 스프린트 목표 문장 작성 | 20~30분 | 5분 | 80% |
| 13 | A/B 테스트 설계서 | 1~1.5시간 | 30분 | 65% |
| 14 | HTML 프로토타입 (3화면) | 2~3시간 (개발자에게 요청 포함) | 30~40분 | 75% |
| 15 | 버그 리포트 정리 | 20~30분 | 5~8분 | 70% |

**전체 평균 절감율**: 약 74%

⚠️ **주의**: 이 숫자는 Copilot 결과를 그대로 쓰는 게 아니라, **검토/수정 시간을 포함한** 실질 절감 추정치입니다. Copilot 결과를 무조건 믿으면 안 됩니다.

## 1.3 Before / After 3가지 비교

### Before/After 1 — PRD 초안 작성

**Before (Copilot 없이)**

```
1. 지난 PRD 파일 찾아서 열기 (5분)
2. 새 파일에 목차 구조 만들기 (20분)
3. 각 섹션 내용 처음부터 작성 (90~120분)
4. 누락된 섹션 발견하고 추가 (20분)
총 소요: 2~2.5시간
```

**After (Copilot 사용)**

```
1. prd-draft.md 파일 생성
2. Chat에 프롬프트 입력 (2분):
```

```
"AI 학습 기록 앱"의 푸시 알림 기능 PRD 초안을 Markdown으로 작성.
목적: 사용자의 학습 습관 형성 지원.
대상: 앱 사용 30일 이상 활성 사용자.

섹션: 배경/문제정의, 목표(성공지표), 사용자 스토리 5개,
      기능 명세, 비기능 요구사항, 스코프, 리스크, 마일스톤.
```

```
3. 생성된 초안 검토 + 회사 실정에 맞게 수정 (30~40분)
총 소요: 35~45분
```

차이: 1.5~2시간 절약. 그리고 처음부터 구조가 잡혀 있어 **누락 섹션이 없습니다**.

---

### Before/After 2 — 회의록에서 JIRA 티켓으로

**Before (Copilot 없이)**

```
스크럼 회의 후 PM이 직접:
1. 회의록 다시 읽으며 액션 아이템 추출 (15분)
2. JIRA 창 열고 티켓 제목 입력 (5분)
3. 각 티켓 설명 작성 (30~40분)
4. 우선순위/담당자/타입 설정 (15분)
총: 65~75분 (8개 티켓 기준)
```

**After (Copilot 사용)**

```
1. 회의록 텍스트를 meeting.md에 붙여넣기
2. 전체 선택 → Chat 사이드바에 다음 프롬프트:
```

```
아래 회의록에서 JIRA 티켓 초안을 추출해줘.
각 티켓: 제목 / 타입(Story or Task or Bug) / 우선순위 /
          담당자 / 설명 2문장 / 인수 조건 2개.

[회의록 붙여넣기]
```

```
3. 결과 검토 → 실제 담당자/스토리포인트 수정 (10~15분)
4. JIRA에 복붙 (10분)
총: 25~30분
```

차이: 40분 이상 절약. 그리고 **티켓 형식이 일관**하게 유지됩니다.

---

### Before/After 3 — 개발자 PR 이해하기

**Before (Copilot 없이)**

```
PM이 개발자 PR 링크를 받아서:
1. GitHub PR 페이지 열기
2. changed files 탭 확인 → 코드 한 줄씩 보기
3. 무슨 의미인지 모르는 부분에서 멈춤
4. 개발자에게 슬랙 질문 (답변 대기 30~60분)
5. 다시 돌아와서 이해 시도
총: 30~90분 (내용 이해 부분에서 변동폭 큼)
```

**After (Copilot 사용)**

```
1. PR의 "Files Changed" 탭에서 diff 텍스트 복사
2. Chat에:
```

```
아래 코드 변경 사항을 PM 입장에서 이해할 수 있게 설명해줘.
- 기술 용어 없이
- 어떤 기능이 어떻게 바뀌는지
- 사용자 경험에 어떤 영향이 있는지
- 내가 기획서에서 확인해야 할 것이 있는가

[diff 붙여넣기]
```

```
3. 설명 읽고 이해 (5~10분)
4. 필요한 경우 추가 질문
총: 10~15분
```

차이: 20~75분 절약. 그리고 **개발자를 기다리지 않아도 됩니다**.

## 1.4 Copilot을 써도 PM의 역할이 사라지지 않는 이유

이 시점에서 한 가지 명확히 해둘 것이 있습니다.

Copilot이 PRD 초안을 만들어주지만, **PM이 없어지지는 않습니다**. 오히려 반대입니다.

| Copilot이 대체하는 것 | Copilot이 대체하지 못하는 것 |
|---------------------|---------------------------|
| 빈 화면에서 구조 잡기 | 실제 사용자 인터뷰와 통찰 |
| 반복적인 형식/포맷 작업 | 어떤 기능을 만들지 결정 |
| 초안 텍스트 생성 | 이해관계자 간 갈등 조율 |
| 엣지케이스 목록 제안 | 트레이드오프 판단 |
| 코드 변경 사항 설명 | 제품 방향성 오너십 |

Copilot이 초안을 빠르게 만들어주기 때문에, PM은 **반복 작업이 아닌 판단과 결정**에 더 많은 시간을 쓸 수 있게 됩니다.

## 1.5 PM 업무 유형별 Copilot 활용 전략

```
문서 생산
├── 처음 쓰는 문서 유형 → Chat으로 구조부터 생성
├── 기존 형식이 있는 문서 → Instruction 파일에 형식 등록 후 Tab 자동완성
└── 반복 작업 (주간 보고 등) → 템플릿 파일 + Tab 자동완성

협업 커뮤니케이션
├── 개발팀에 전달 → "기술 스펙 변환" 프롬프트
├── 임원 보고 → "1페이지 요약" 프롬프트
└── 이해관계자 이메일 → "이해관계자 업데이트" 프롬프트

기술 이해
├── PR 이해 → "/explain 코드 변경 사항"
├── API 명세 → "비기술자용 설명" 프롬프트
└── 에러 로그 → "에러 해석" 프롬프트

분석 & 기획
├── 엣지케이스 발굴 → "엣지케이스 발굴" 프롬프트
├── 우선순위 정리 → "MoSCoW 분류" 프롬프트
└── A/B 테스트 설계 → "A/B 테스트 설계" 프롬프트
```

```
간단한 신기능 PRD 초안을 Markdown으로 작성해줘.

기능: 모바일 앱 다크 모드 지원

- 어떤 부분을 내가 수정해야 할까요?
- 어떤 부분은 바로 쓸 수 있나요?

- 다음 스프린트에 Story 2개, Task 1개 정도 예상
- 출시 목표: 8월 첫째 주

결정 사항:
- 알림 설정 화면 리디자인 진행
- 카테고리: 공지/마케팅/업데이트/개인 4가지
- 마케팅 알림은 기본 OFF
```

## 핵심 포인트

1. PM 업무의 50~60%는 문서·정보 정리·커뮤니케이션이며, Copilot이 이 영역을 평균 74% 줄여줍니다
2. Copilot은 **초안 생성기**입니다. 결과를 그대로 쓰지 말고, 항상 내용 검토와 수정이 필요합니다
3. PRD 작성, 사용자 스토리 생성, 회의록 티켓 변환, PR 이해가 PM에게 가장 즉각적인 ROI를 제공합니다
4. Copilot이 반복 작업을 대체하면 PM은 **판단·결정·관계 조율**에 더 집중할 수 있습니다
5. 처음에는 어색하더라도 실제 업무 소재로 바로 써봐야 습관이 생깁니다
