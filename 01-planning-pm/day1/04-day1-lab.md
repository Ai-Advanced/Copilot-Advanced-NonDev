# 04. Day 1 종합 실습 — "AI 학습 기록 앱" 기획 3종 세트

## 학습 목표

- Day 1에서 배운 PRD 작성, 사용자 스토리, 요구사항 정의를 하나의 흐름으로 연결한다
- 가상 신제품의 PRD + 사용자 스토리 + 요구사항 정의서를 실제로 완성한다
- Copilot 결과를 검토하고 수정하는 습관을 자연스럽게 익힌다

**예상 소요**: 60분 (실습 위주)

---

## 실습 개요

오늘 만들 것은 가상 신제품 **"AI 학습 기록 앱 (LearnLog)"**의 신기능 기획 문서 3종 세트입니다.

```
완성할 파일 구조:
learnlog-feature/
├── prd.md               # PRD (기획서)
├── user-stories.md      # 사용자 스토리 + 인수 조건
└── requirements.md      # 기능 요구사항 명세서
```

세 파일은 독립적이지만 서로 연결되어 있습니다.
`prd.md`의 목표 → `user-stories.md`의 스토리 → `requirements.md`의 요구사항이 논리적으로 이어져야 합니다.

---

## 제품/기능 배경

**제품**: LearnLog — AI 기반 학습 기록 앱 (모바일 iOS/Android)
**현재 상태**: 기본 학습 기록 기능 출시 완료, MAU 5만 명
**신기능**: **"AI 학습 코치"** — 사용자의 학습 기록 패턴을 분석해서 맞춤형 학습 계획과 동기부여 메시지를 제공하는 기능

**배경 데이터 (가상)**:
- 신규 사용자 Day 14 이탈율: 62%
- "무엇을 어떻게 공부해야 할지 모르겠다"는 CS 문의: 월 평균 430건
- 경쟁사 앱 A가 유사 기능 출시 후 다운로드 30% 증가 (가상 수치)

## 실습 1. PRD 작성 (25분)

### Step 1: 작업 폴더 및 파일 설정

VS Code에서 `learnlog-feature` 폴더를 만들고, `.github/copilot-instructions.md` 파일을 만드세요:

```markdown
# LearnLog 기획 작업 공간

## PRD 규칙
- 모든 성공 지표는 측정 가능한 수치로 작성
- 스코프에는 반드시 In-Scope와 Out-of-Scope 모두 명시
- 리스크는 발생가능성(H/M/L)과 영향도(H/M/L)를 함께 표기
- 사용자 스토리는 "As a / I want to / so that" 형식

## 용어 정의
- "코치": AI 학습 코치 기능 전체
- "학습 기록": 사용자가 입력한 공부 내용/시간/과목
- "분석 리포트": AI가 생성하는 학습 패턴 분석 결과
```

### Step 2: PRD 초안 생성

`prd.md` 파일을 만들고 Chat에 다음 프롬프트를 입력하세요:

```
LearnLog 앱의 "AI 학습 코치" 기능 PRD 초안을 Markdown으로 작성해줘.

제품 배경:
- LearnLog: 모바일 학습 기록 앱, MAU 5만 명
- 문제: 신규 사용자 Day 14 이탈율 62%, "무엇을 어떻게 공부할지 모르겠다" CS 문의 월 430건
- 경쟁사 동향: 유사 기능 출시 후 경쟁사 다운로드 30% 증가

기능 설명:
- 사용자의 학습 기록(과목/시간/내용)을 AI가 분석
- 매주 월요일 맞춤형 학습 계획 제안
- 매일 저녁 동기부여 메시지 + 오늘의 학습 요약 푸시 알림
- 목표 달성률 시각화 (주간/월간 차트)

대상 사용자:
- 20~35세 직장인, 자기계발 공부 중
- 혼자 공부 계획 세우기 어려워하는 유형

섹션:
1. 배경 및 문제 정의 (Why now 포함)
2. 목표 (Primary Metric 1개 + Secondary 2개 + Guardrail 1개, 각 baseline + target)
3. 사용자 스토리 (5개, Happy Path 3개 + 엣지케이스 2개)
4. 기능 명세 (12개 항목, 각 우선순위 표기)
5. 비기능 요구사항 (성능 2개, 보안 2개, 접근성 1개)
6. 스코프 (In-Scope 6개, Out-of-Scope 4개)
7. 리스크 (4개, 각 발생가능성/영향도/대응방안)
8. 마일스톤 (Discovery/Alpha/Beta/GA 4단계 표)
```

### Step 3: PRD 검토 및 수정

생성된 PRD를 아래 기준으로 직접 검토하세요:

```
체크리스트:
□ 성공 지표 중 측정 불가한 표현이 있는가? ("향상", "증가" 등)
□ Out-of-Scope 항목이 충분히 구체적인가?
□ 리스크에 발생가능성/영향도가 모두 표기되어 있는가?
□ 마일스톤 날짜가 현실적인가?
□ 기능 명세가 개발팀이 오해할 여지가 있는가?
```

수정이 필요한 부분을 직접 편집하거나, Chat으로 개선 요청하세요:

```
위 PRD에서 다음을 수정해줘:
1. 목표 섹션의 측정 불가 표현을 모두 구체적인 수치로 교체
2. Out-of-Scope 항목에 "AI가 실시간 대화하는 챗봇 기능"과 "외부 캘린더 연동" 추가
3. 리스크에 "AI 분석 오류로 잘못된 학습 계획 제시" 리스크 추가 (발생가능성: High, 영향도: Medium)
```

## 실습 2. 사용자 스토리 작성 (20분)

### Step 1: 사용자 스토리 대량 생성

`user-stories.md` 파일을 만들고 Chat에 입력하세요:

```
LearnLog "AI 학습 코치" 기능의 사용자 스토리를 작성해줘.

사용자 유형:
- 신규 사용자 (앱 사용 7일 이내, 아직 학습 기록 부족)
- 활성 사용자 (학습 기록 30일 이상 보유)
- 이탈 후 복귀 사용자 (2주 이상 미접속 후 돌아온)

카테고리별 스토리:
1. AI 학습 계획 제안 받기 — 4개
2. 동기부여 메시지 및 알림 — 3개
3. 학습 패턴 분석 리포트 보기 — 4개
4. AI 코치 설정 (알림 시간, 과목 선호 등) — 3개
5. 에러/엣지케이스 (데이터 부족, 잘못된 제안, 알림 오류) — 4개

형식:
## [카테고리명]

### ST-[번호]: [스토리 제목]
As a [사용자 유형],
I want to [행동],
so that [가치].

**인수 조건**:
- Given [초기 상태]
  When [사용자 행동]
  Then [기대 결과]
- [두 번째 인수 조건]
```

### Step 2: INVEST 검증

생성된 스토리 중 ST-01 ~ ST-06 (6개)을 INVEST 검증하세요:

```
아래 사용자 스토리들을 INVEST 원칙으로 검토해줘.
각 스토리에 I/N/V/E/S/T 항목별 ✅/❌ 표시.
❌ 항목이 있으면 반드시 개선 버전 제시.

[ST-01 ~ ST-06 붙여넣기]
```

### Step 3: 누락 스토리 보완

다음 프롬프트로 놓친 시나리오를 찾으세요:

```
위에서 작성한 AI 학습 코치 사용자 스토리에서 놓친 시나리오를 찾아줘.
특히 다음 관점에서 추가 스토리가 필요한지 확인:
- AI 분석 결과에 동의하지 않을 때 사용자 피드백
- 개인정보/학습 데이터 삭제 요청
- AI 코치 기능 비활성화 (OPT-OUT)
- 학습 과목이 AI가 인식하지 못하는 특수한 분야일 때

필요하면 추가 스토리 작성. 필요 없으면 이유 설명.
```

## 실습 3. 요구사항 명세서 작성 (15분)

### Step 1: 기능 요구사항 생성

`requirements.md` 파일을 만들고 Chat에 입력하세요:

```
LearnLog AI 학습 코치 기능의 기능 요구사항 명세서를 작성해줘.

기반 자료:
- PRD 기능 명세 섹션의 12개 항목 (prd.md 참고)
- 사용자 스토리 18개 (user-stories.md 참고)

출력 형식:
# 기능 요구사항 명세서
## 1. 기능 요구사항 (Functional Requirements)

| ID | 분류 | 우선순위 | 설명 | 연관 스토리 |
|----|------|---------|------|------------|

FR-001 부터 시작, 우선순위는 Highest/High/Medium/Low.

## 2. 비기능 요구사항 (Non-Functional Requirements)

### 2.1 성능
### 2.2 보안 및 개인정보
### 2.3 접근성
### 2.4 가용성

각 비기능 요구사항도 NFR-001 형식 ID와 측정 가능한 기준 포함.

## 3. 데이터 요구사항
- AI 분석에 필요한 최소 학습 기록 수
- 데이터 보존 기간
- 삭제 요청 처리 기간 (개인정보보호법 기준)
```

### Step 2: 최종 문서 연결 확인

세 파일이 완성되면, 다음 검토를 수행하세요:

```
PRD의 목표 지표, 사용자 스토리, 요구사항 명세서가 서로 일관성 있는지 확인해줘.

확인 항목:
1. PRD 성공 지표와 연관된 기능 요구사항이 있는가?
2. 모든 사용자 스토리에 대응하는 기능 요구사항이 있는가?
3. PRD의 Out-of-Scope 항목이 요구사항에 포함되지 않았는가?
4. 비기능 요구사항이 PRD 기능 명세와 충돌하지 않는가?

불일치 항목이 있으면 어느 문서를 어떻게 수정해야 하는지 알려줘.
```

## 실습 4. 이해관계자 커뮤니케이션 변환 (선택, 10분)

완성된 PRD를 두 가지 버전으로 변환해보세요.

**임원 보고용 요약**:

```
위 AI 학습 코치 PRD를 임원 보고용 1페이지 요약으로 변환해줘.

요구사항:
- 500자 이내
- 기술 용어 없이 비즈니스 언어로
- 구조: 문제(수치) → 솔루션(2줄) → 기대 효과(수치) → 의사결정 필요 사항
- 톤: 자신감 있고 명확하게
```

**개발팀 전달용 기술 스펙 요약**:

```
위 PRD에서 개발팀이 기술 검토 미팅 전에 알아야 할 핵심 기술 요구사항만 뽑아줘.

포함:
- API 엔드포인트 목록 (추정)
- 예상 데이터 모델 변경 사항
- 성능 요구사항 수치
- 보안 고려사항
- 미결 기술 결정 사항 (개발팀이 결정해야 할 것)

톤: 간결하고 기술적으로
```
