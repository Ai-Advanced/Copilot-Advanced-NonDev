# 07. Copilot으로 인터랙티브 프로토타입 만들기

## 학습 목표

- Copilot Chat 프롬프트만으로 클릭 가능한 HTML 목업을 만드는 방법을 안다
- 기획서의 텍스트 설명을 화면으로 변환하는 프롬프트 패턴을 익힌다
- 개발자 없이 이해관계자에게 보여줄 수 있는 3화면 프로토타입을 완성한다

**예상 소요**: 50분 (이론 10분 + 실습 40분)

---

## 7.1 왜 PM이 프로토타입을 직접 만드는가

"이 화면이 어떻게 생겼으면 좋겠어요"라는 말을 개발자나 디자이너에게 전달할 때,
텍스트 기획서와 실제 화면 사이에는 항상 해석의 차이가 생깁니다.

빠른 프로토타입이 필요한 상황:
- 임원 보고 전날, 디자이너가 바쁠 때
- 사용자 인터뷰 전에 화면 아이디어를 검증하고 싶을 때
- 개발팀에게 "이렇게 생긴 것"을 보여줘야 할 때
- 경쟁사 기능을 빠르게 재현해서 비교할 때

이전까지는 Figma를 배우거나, 디자이너에게 요청하거나, PowerPoint로 어설픈 와이어프레임을 만들었습니다.

Copilot을 쓰면 **HTML + CSS로 클릭 가능한 목업**을 프롬프트 3번으로 만들 수 있습니다.

---

## 7.2 이 방법의 범위와 한계

**할 수 있는 것**:
- 단일 HTML 파일 안에서 화면 전환 (JavaScript 최소 사용)
- 버튼 클릭으로 다음 화면(섹션)으로 이동
- 실제처럼 보이는 플레이스홀더 UI
- 모바일 화면 레이아웃 (390px 기준)
- 브라우저에서 바로 열어서 공유

**할 수 없는 것**:
- 실제 데이터 저장/조회 (백엔드 없음)
- 복잡한 인터랙션 (드래그앤드롭, 무한스크롤 등)
- 디자인 시스템 수준의 정교함 (Figma 수준 기대 금지)

⚠️ **이 프로토타입은 아이디어를 빠르게 보여주기 위한 도구입니다. 최종 디자인이나 개발 스펙으로 쓰면 안 됩니다.**

## 7.3 첫 번째 프로토타입 — 모바일 화면 만들기

### 기본 프롬프트 구조

```
[기능명] 화면의 HTML 프로토타입을 만들어줘.

화면 구성:
[화면에 있어야 할 UI 요소 설명]

기술 요구사항:
- 단일 HTML 파일 (CSS는 <style> 태그 내부)
- JavaScript 최소화 (화면 전환 정도만)
- 모바일 레이아웃 (max-width: 390px, 중앙 정렬)
- 한국어 플레이스홀더 텍스트
- 스타일: 깔끔하고 현대적
  - 배경: #F8F9FA
  - 메인 컬러: #4F46E5 (인디고)
  - 텍스트: #1F2937
  - 카드: 흰 배경, 둥근 모서리(12px), 그림자 가볍게
```

### 화면 전환 구현 방법

단일 HTML 파일에서 여러 화면을 보여주는 간단한 패턴:

```html
<!-- 각 화면을 div.screen으로 구분 -->
<div id="screen-home" class="screen active">
  <!-- 홈 화면 내용 -->
  <button onclick="showScreen('screen-detail')">상세 보기</button>
</div>

<div id="screen-detail" class="screen">
  <!-- 상세 화면 내용 -->
</div>

<script>
function showScreen(screenId) {
  document.querySelectorAll('.screen').forEach(s => s.classList.remove('active'));
  document.getElementById(screenId).classList.add('active');
}
</script>

<style>
.screen { display: none; }
.screen.active { display: block; }
</style>
```

이 패턴을 Chat에 설명하고 Copilot이 자동으로 적용하도록 프롬프트에 명시하세요:

```
화면 전환은 JavaScript를 사용하되, 각 화면을 id가 있는 div로 구분하고
showScreen('화면id') 함수로 전환하는 방식으로 구현해줘.
```

## 7.4 3화면 프로토타입 만들기 — LearnLog AI 코치

### 만들 화면

```
화면 1: AI 코치 메인
    ↓ (버튼 클릭)
화면 2: 이번 주 학습 계획 상세
    ↓ (버튼 클릭)
화면 3: 학습 기록이 부족할 때 (빈 상태)
```

### 화면 1 프롬프트

```
LearnLog 앱의 "AI 코치 메인" 화면 HTML 프로토타입.

화면 구성 (위에서 아래):
1. 상단 헤더: "AI 학습 코치" 제목 + 설정 아이콘(⚙️)
2. 인사말 섹션: "안녕하세요, 박지은님! 오늘도 화이팅 💪" (이름은 플레이스홀더)
3. 오늘의 동기부여 메시지 카드:
   - 인디고 배경
   - 인용문 형식: "매일 30분이 1년 후 여러분을 바꿉니다"
   - 날짜: "2026년 7월 20일 월요일"
4. 이번 주 학습 계획 섹션:
   - 섹션 제목 "이번 주 계획" + "자세히 보기" 링크
   - 과목 3개 카드 (영어/수학/프로그래밍, 각 목표 시간 표시)
   - 진행률 프로그레스 바
5. 하단 탭바: 홈/기록/코치(선택됨)/프로필 4개

기술:
- 단일 HTML 파일
- 모바일 390px
- "자세히 보기" 클릭 시 화면 2로 전환 (showScreen 함수)
- 메인 컬러 #4F46E5
```

### 화면 2 프롬프트 (화면 1 완성 후)

```
위 HTML 파일에 화면 2를 추가해줘.

화면 2: "이번 주 학습 계획 상세"

구성:
1. 뒤로가기 버튼 ← + "이번 주 계획" 제목
2. 주간 요약 카드:
   - 목표: 5일 / 총 7시간 30분
   - 달성: 3일 / 4시간 20분 (진행률 58%)
3. 요일별 계획 목록 (월~일):
   - 완료한 날: ✅ + 과목명 + 실제 시간
   - 오늘: 강조 표시 + "기록하기" 버튼
   - 미래: 회색 + 예정 과목
4. AI 추천 메시지 카드: "목요일에 영어를 30분만 더 하면 주간 목표 달성이에요!"
5. 하단 탭바 동일

뒤로가기 클릭 시 화면 1로 전환.
화면 이름: screen-weekly-plan
```

### 화면 3 프롬프트 (빈 상태)

```
위 HTML 파일에 화면 3을 추가해줘.

화면 3: "데이터 부족 - AI 코치 잠금 상태"

구성:
1. 상단 헤더 동일
2. 잠금 상태 일러스트 자리 (이모지 🔒 크게)
3. 안내 메시지:
   - 큰 텍스트: "아직 학습 데이터가 부족해요"
   - 작은 텍스트: "AI 코치가 분석을 시작하려면 최소 7일의 학습 기록이 필요합니다"
4. 진행 상태: "현재 3일 기록됨 / 7일 필요" (프로그레스 바)
5. CTA 버튼: "오늘 학습 기록하기" (인디고)
6. 하단 탭바 동일

이 화면은 별도 접근 방법 없이, 화면 1에서 "기록 부족" 배너를 클릭했을 때 전환.
화면 1에 배너 추가: 상단 인사말 아래에 "📊 3/7일 기록 완료 — AI 코치 활성화까지 4일 더!" 바 추가.
```

## 7.5 프로토타입 개선 프롬프트

초안이 나왔으면 세부 조정:

**색상/스타일 변경**:
```
위 프로토타입의 메인 컬러를 #4F46E5(인디고)에서 #10B981(에메랄드)로 바꿔줘.
버튼과 프로그레스 바, 선택된 탭 아이콘 색상 모두 변경.
```

**반응형 조정**:
```
현재 390px 고정인데, 데스크탑(768px 이상)에서 볼 때도
중앙에 390px 폰 프레임처럼 보이도록 조정해줘.
배경은 #E5E7EB, 가운데 흰 영역이 폰처럼 보이게.
```

**애니메이션 추가**:
```
화면 전환 시 슬라이드 인 애니메이션 추가해줘.
오른쪽에서 왼쪽으로 슬라이드. CSS transition 사용 (JavaScript 최소화).
```

**접근성 개선**:
```
위 HTML에 기본 접근성 속성을 추가해줘.
- 버튼에 aria-label
- 이미지 자리에 alt 텍스트
- 색상 대비가 낮은 텍스트 색상 개선
- 키보드 탭 네비게이션 가능하도록
```

## 실습

### 실습 1. 기본 화면 1개 만들기 (15분)

VS Code에서 `prototype.html` 파일을 만들고 Chat에 다음 프롬프트를 입력하세요:

```
LearnLog 앱의 홈 화면 HTML 프로토타입을 만들어줘.

화면 구성:
1. 상단: 앱 이름 "LearnLog" + 오늘 날짜
2. 오늘의 학습 현황 카드: 과목명, 학습 시간, 완료/미완료 상태
3. 오늘 기록된 학습 목록 (3개 예시 항목)
4. + 기록 추가 버튼 (하단 우측 플로팅)
5. 하단 탭바 4개

기술:
- 단일 HTML 파일 (<style> 태그 포함)
- 모바일 390px 중앙 정렬
- 한국어 플레이스홀더
- 깔끔하고 현대적인 디자인
```

생성된 코드를 파일에 붙여넣고, 파일 탐색기에서 더블클릭해서 브라우저로 열어보세요.

### 실습 2. 3화면 프로토타입 완성 (20분)

7.4절의 프롬프트 3개를 순서대로 적용해서 AI 코치 3화면 프로토타입을 완성하세요.

각 화면 생성 후 브라우저에서 확인하고, 어색한 부분이 있으면 즉시 수정 요청하세요.

완성 기준:
- 화면 1: AI 코치 메인 (렌더링 완료)
- 화면 2: 이번 주 계획 상세 (화면 1에서 버튼 클릭 시 이동)
- 화면 3: 빈 상태 (화면 1의 배너 클릭 시 이동)
- 모든 뒤로가기 버튼이 작동

---

### 실습 3. 이해관계자 공유 준비 (5분)

완성된 `prototype.html` 파일을 이해관계자에게 공유하는 방법:

1. 파일을 이메일 첨부로 전달 → 받는 사람이 더블클릭으로 브라우저에서 열기
2. GitHub Repository에 올리면 GitHub Pages로 URL 공유 가능
3. 슬랙/Teams 채널에 파일 드롭

내 프로토타입에 간단한 설명 헤더를 추가하세요:

```
파일 맨 위에 다음 배너를 추가해줘:
- 배경: 노란색 (#FEF3C7)
- 텍스트: "⚠️ 이것은 기획 목적의 프로토타입입니다. 최종 디자인이 아닙니다."
- 작은 텍스트: "문의: [이름] | 작성일: 2026-07-20"
```

## 핵심 포인트

1. Copilot으로 만드는 HTML 프로토타입은 **아이디어를 빠르게 보여주기 위한 도구**입니다. Figma 수준의 완성도를 기대하지 마세요
2. **단일 HTML 파일 + showScreen 함수 패턴**이 PM 프로토타입의 핵심입니다. 이 패턴 하나로 여러 화면을 이어붙일 수 있습니다
3. 화면을 한 번에 다 만들려 하지 말고, **한 화면씩 만들고 확인 후** 다음 화면을 추가하는 방식이 오류가 적습니다
4. 프로토타입 상단에 **"기획 목적 프로토타입" 배너**를 반드시 넣으세요. 이해관계자가 완성된 제품으로 오해하는 경우가 많습니다
5. 디자인보다 **플로우와 콘텐츠**에 집중하세요. 색상이나 여백보다 "이 버튼을 누르면 어디로 가는가"가 핵심입니다
