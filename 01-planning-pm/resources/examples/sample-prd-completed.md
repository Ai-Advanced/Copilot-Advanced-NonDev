## 1. 배경 및 문제 정의

<!-- [Copilot] 아래 섹션 구조는 Copilot이 생성. 수치와 구체적 사례는 직접 작성 -->

### 1.1 현황

카페인(CaféIn)은 사용자가 동네 카페를 지도에서 검색하고 즐겨찾기를 추가하는 앱입니다. 현재 MAU 8만 명, 재방문율 Day 30 기준 22%입니다.

사용자 인터뷰(N=20, 2026년 6월)에서 공통으로 나온 피드백:

> "지도에서 카페를 찾았는데, 실제로 가보면 생각과 다를 때가 많아요. 다른 사람들이 어떻게 생각하는지 알고 싶어요."
> — 인터뷰 참여자 17명 중 14명이 유사 발언

### 1.2 문제 정의

**핵심 문제**: 사용자가 카페를 방문하기 전에 신뢰할 수 있는 동료 리뷰 정보가 없어서, 앱을 방문 결정의 최종 단계에서 사용하지 않는다.

페인포인트:
- 카페 상세 화면에 영업시간/위치만 있고 리뷰가 없음
- 네이버/카카오 지도로 이탈해서 리뷰 확인 후 다시 돌아오는 패턴 (이탈율 41%)
- 앱에서 검색→방문까지 이어지는 전환율이 경쟁사 대비 낮음

### 1.3 Why Now

<!-- [직접 작성] 경쟁사 동향은 Copilot이 생성할 수 없으므로 직접 작성 -->

- 경쟁 앱 "커피찾기"가 2026년 5월 리뷰 기능 출시 후 MAU 35% 증가 (언론 보도 기준)
- 내부 NPS 설문에서 "리뷰가 없어서 아쉽다" 항목이 2위 (응답자 중 38%)
- 기술팀의 리뷰 시스템 인프라 준비 완료 (별도 스파이크 완료, 2주 내 착수 가능)

### 1.4 해결하지 않을 경우 리스크

리뷰 기능 없이 6개월 추가 경과 시 예상 시나리오:
- Day 30 재방문율 22% → 15% 이하로 하락 예상
- 경쟁사와 기능 격차 확대 → 신규 유입 감소
- "앱 쓸 이유가 없다"는 인식 강화

## 3. 사용자 페르소나

<!-- [Copilot] 페르소나 구조 생성. 세부 내용은 인터뷰 데이터 기반으로 수정 -->

### 페르소나 A: 카페 탐험가 이지수 (28세, 콘텐츠 마케터)

- **기술 수준**: 높음 (디지털 네이티브, 앱 리뷰 작성 경험 있음)
- **핵심 목표**: 새로운 카페를 발견하고 SNS에 공유할 만한 인증샷 공간 찾기
- **주요 페인포인트**: 여러 앱을 동시에 열어야 해서 번거로움. 믿을 수 있는 리뷰인지 모르겠음
- **이 기능 활용**: 방문 전 리뷰 확인 + 방문 후 별점/한줄평 작성

### 페르소나 B: 재택근무자 박민준 (34세, 개발자)

- **기술 수준**: 높음, 하지만 SNS보다 실용적 정보 선호
- **핵심 목표**: 조용하고 와이파이 잘 되는 카페 찾기. 매일 가는 카페 패턴 있음
- **주요 페인포인트**: 리뷰가 너무 많으면 읽기 귀찮음. 핵심 정보(와이파이/콘센트/소음)만 빠르게 확인하고 싶음
- **이 기능 활용**: 태그 기반 필터로 "조용함/와이파이 빠름" 조건 확인

5. As a 카페 운영자 (향후), I want to 내 카페의 리뷰에 답글을 남기고 싶다, so that 고객 피드백에 응답할 수 있다.

## 5. 기능 명세

<!-- [Copilot] 기능 목록 초안 생성. 우선순위와 상세 설명은 직접 조정 -->

| ID | 기능명 | 설명 | 우선순위 |
|----|--------|------|---------|
| F-01 | 카페 별점 표시 | 카페 목록/상세에서 평균 별점(★) + 리뷰 수 표시 | Highest |
| F-02 | 리뷰 목록 조회 | 카페 상세에서 최근 리뷰 최대 20개 표시 | Highest |
| F-03 | 별점 작성 | 1~5점 별점 선택 + 최대 200자 텍스트 리뷰 | Highest |
| F-04 | 태그 선택 | 리뷰 작성 시 태그 선택 (와이파이/콘센트/소음/혼잡도 등 10개) | High |
| F-05 | 내 리뷰 목록 | 프로필 탭에서 내가 작성한 리뷰 목록 조회 | High |

| F-07 | 리뷰 삭제 | 작성자 본인이 자신의 리뷰 삭제 | Medium |

| F-09 | 리뷰 정렬 | 최신순 / 별점 높은 순 / 도움됨 순 정렬 | Medium |
| F-10 | 태그 필터 | 리뷰 목록에서 특정 태그 가진 리뷰만 보기 | Low |
| F-11 | 중복 리뷰 방지 | 같은 카페에 리뷰 1개만 허용 (수정은 가능) | Highest |
| F-12 | 리뷰 모더레이션 | 욕설/스팸 필터링 (자동 + 신고 기반) | High |

<!-- [직접 작성] F-11, F-12는 Copilot이 빠뜨려서 직접 추가 -->

### 상세: F-03 별점 작성

**설명**: 사용자가 방문한 카페에 1~5점 별점과 최대 200자 텍스트 리뷰를 작성할 수 있다. 로그인된 사용자만 작성 가능하며, 카페당 1개 리뷰 제한이 적용된다.

**입력값**:
- rating: 정수 1~5 (필수)
- comment: 문자열 0~200자 (선택)
- tags: 미리 정의된 태그 ID 배열, 최대 5개 (선택)

**출력/결과**:
- 리뷰 저장 성공 시 카페 상세 화면으로 복귀, "리뷰가 등록됐습니다" 토스트 메시지
- 카페의 평균 별점과 리뷰 수가 즉시 업데이트됨 (낙관적 업데이트)

**예외 처리**:
- 비로그인 상태 → "로그인 후 리뷰를 남길 수 있습니다" 안내 + 로그인 화면 이동
- 이미 리뷰 작성한 카페 → "이미 작성한 리뷰가 있습니다. 수정하시겠습니까?" 확인 다이얼로그
- 금지어 포함 → 저장 전 "부적절한 표현이 포함됐습니다" 안내
- 네트워크 오류 → "저장에 실패했습니다. 다시 시도해주세요" + 재시도 버튼

## 6. 비기능 요구사항

<!-- [Copilot] 구조 생성. 수치는 직접 조정 -->

### 6.1 성능

- 리뷰 목록 로딩 (20개): 1.5초 이내 (P95, LTE 환경)
- 리뷰 작성 저장: 2초 이내 응답
- 카페 목록에서 별점 표시: 기존 카페 목록 API 응답 시간 +200ms 이내

### 6.2 보안

- 리뷰 내용은 XSS 방지를 위해 서버 측 이스케이프 처리
- 신고된 리뷰는 운영팀 검토 완료 전까지 작성자에게만 표시
- 리뷰 작성자 정보(닉네임만 노출, 이메일/전화번호 비노출)

### 6.3 접근성

- 별점 UI는 키보드로 선택 가능 (1~5 키 또는 화살표)
- 별점 이미지에 aria-label: "5점 중 [N]점"

### 6.4 가용성

- 리뷰 시스템 장애 시 카페 기본 정보 화면은 정상 표시 (graceful degradation)
- 리뷰 영역에 "일시적으로 이용할 수 없습니다" 메시지 표시

## Copilot 활용 메모 (작성자 노트)

> 이 PRD를 Copilot으로 작성한 과정 요약 — 다음 사람을 위한 참고

**Copilot이 잘 해준 것**:
- 전체 섹션 구조 잡기 (배경/목표/스토리/명세/스코프/리스크/마일스톤)
- 기능 명세 목록 10개 초안
- 리스크 4개 항목 기본 구조

**직접 수정한 것**:
- 성공 지표 수치 (baseline, target 모두 직접 입력)
- 사용자 인터뷰 인용문 추가
- F-11(중복 방지), F-12(모더레이션) — Copilot이 누락
- AI 요약 기능 Out-of-Scope 이동 (Copilot이 In-Scope로 제안했으나 제외 결정)
- Guardrail 지표 (앱 스토어 평점) — Copilot이 누락
- 카페 운영자 답글 Out-of-Scope 이유 구체화

**총 소요 시간**: 약 55분 (Copilot 없이 추정 2.5~3시간)

**가장 유용했던 프롬프트**:
```
이 PRD에서 놓친 엣지케이스와 Out-of-Scope 항목을 찾아줘.
특히 어뷰징 방지, 개인정보, 운영 부하 관점에서.
```
→ 이 프롬프트 하나로 F-11, F-12, 리스크 3번이 추가됨.
