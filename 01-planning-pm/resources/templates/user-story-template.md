### ST-001: [스토리 제목]

> **사용자 스토리**

**As a** [사용자 유형],
**I want to** [사용자가 하고 싶은 행동],
**so that** [이 행동으로 얻는 가치 또는 목적].

> **INVEST 체크**

| 원칙 | 상태 | 비고 |
|------|------|------|
| Independent (독립적) | ✅ / ❌ | |
| Negotiable (협상 가능) | ✅ / ❌ | |
| Valuable (가치 있음) | ✅ / ❌ | |
| Estimable (추정 가능) | ✅ / ❌ | |
| Small (작은 단위) | ✅ / ❌ | |
| Testable (테스트 가능) | ✅ / ❌ | |

> **인수 조건 (Acceptance Criteria)**

```gherkin
Scenario: [정상 흐름 — Happy Path]
  Given [초기 상태 또는 사전 조건]
  When  [사용자가 취하는 행동]
  Then  [기대되는 결과]
  And   [추가 기대 결과 — 있는 경우]
```

```gherkin
Scenario: [에러 케이스 1 — 에러 이름]
  Given [초기 상태]
  When  [에러를 유발하는 사용자 행동]
  Then  [에러 상황에서 기대되는 시스템 동작]
```

```gherkin
Scenario: [에러 케이스 2 — 에러 이름]
  Given [초기 상태]
  When  [에러를 유발하는 사용자 행동]
  Then  [기대되는 결과]
```

## 엣지케이스 체크리스트

스토리를 완성한 후, 아래 관점에서 빠진 케이스가 없는지 확인하세요.

| 관점 | 확인 질문 | 커버 여부 |
|------|-----------|----------|
| 입력값 경계 | 입력값이 비어있으면? 너무 길면? 특수문자면? | ✅ / ❌ / 해당 없음 |
| 권한 경계 | 비로그인 접근? 다른 사용자 데이터 접근? | ✅ / ❌ / 해당 없음 |
| 동시성 | 여러 탭 동시 사용? 두 명이 동시에 같은 데이터 수정? | ✅ / ❌ / 해당 없음 |
| 네트워크/시스템 | 제출 중 인터넷 끊김? 서버 타임아웃? | ✅ / ❌ / 해당 없음 |
| 비즈니스 규칙 | 최솟값/최댓값 초과? 특수 상태의 사용자? | ✅ / ❌ / 해당 없음 |
| 데이터 없음 | 빈 목록? 첫 사용자? 데이터 로딩 실패? | ✅ / ❌ / 해당 없음 |

## Copilot 프롬프트 참고

이 파일 작업 시 유용한 프롬프트:

```
# 스토리 대량 생성

각 스토리에 인수 조건 2개.

# INVEST 검증
아래 스토리들을 INVEST 원칙으로 검토. 각 항목 ✅/❌ 표시 + ❌이면 개선안.
[스토리 목록]

# Gherkin 변환
아래 스토리의 인수 조건을 Gherkin Given-When-Then으로 작성.
Happy Path 1개 + 에러 케이스 2개 이상.
[스토리]

# 엣지케이스 발굴
[기능명]에서 PM이 놓치기 쉬운 엣지케이스를 5가지 관점(입력/권한/동시성/네트워크/비즈니스규칙)에서 각 3개씩 도출.
```
