# 04. Day 1 종합 실습 — 신규 리드 20명 세일즈 시퀀스

## 실습 개요

Day 1에서 배운 모든 것을 하나의 실전 시나리오로 통합합니다.
**영업 담당자로서, 신규 리드 20명을 위한 세일즈 시퀀스 전체를 직접 제작합니다.**

```
총 소요 시간: 60분
혼자 학습 시: 각 단계를 순서대로 진행
```

## 실습 시나리오

### 배경

탠건소프트 영업팀에 새로운 인바운드 리드 20명이 들어왔습니다. 이 리드들은 지난주 열린 "데이터 자동화 트렌드 2026" 웨비나에 참가한 기업 담당자들입니다. 웨비나 참가자 명단과 기본 정보만 있고, 아직 아무도 컨택하지 않은 상태입니다.

**당신의 미션**: 이 20명을 대상으로 완전한 세일즈 시퀀스를 만들고, 3개 업종에 맞는 제안서 초안 3종도 준비합니다.

## Phase 1. 세그먼트 분석 (10분)

### 목표

20명을 의미 있는 그룹으로 나눠서 메시지를 그룹별로 개인화합니다.

### 실습 1-1. 세그먼트 분류

Copilot Chat에 아래 프롬프트를 실행하세요:

```
위 리드 20명을 다음 기준으로 세그먼트 분류해줘.

세그먼트 기준:
A. 업종 유사성 (메시지 유사하게 쓸 수 있는 그룹)
B. 회사 규모 (스타트업 <50명 / 중소 50~200명 / 중견 200~1000명)
C. Pain Point 유사성 (실시간 데이터 / 레거시 연동 / 리포트 자동화)
D. 의사결정 속도 추정 (직책 기반: CTO/IT팀장 = 빠름 / TF = 중간 / 팀장 = 느림)

출력:
1. 세그먼트별 리드 목록 (Markdown 표)
2. 각 세그먼트에 맞는 이메일 핵심 메시지 1~2문장
3. 먼저 공략할 세그먼트 추천 + 이유
```

### 실습 1-2. 우선순위 리드 선정

```
위 세그먼트 분류에서 가장 빠른 전환이 예상되는 Top 5 리드를 뽑아줘.

기준:
- 의사결정 권한이 있는 직책 (CTO, IT팀장, TF)
- Pain Point가 CloudPipe로 직접 해결 가능
- 회사 규모가 Growth 요금제에 맞는 수준

출력: Top 5 리드 + 각각 선정 이유 + 첫 접근 전략 한 줄
```

## Phase 2. 콜드 이메일 시퀀스 제작 (20분)

### 목표

세그먼트별 맞춤 이메일 + 팔로업 3단계를 만듭니다.

### 실습 2-1. 제조업 세그먼트 이메일 시퀀스

```
제조업 세그먼트 (이민수 차장, ABC제조 IT팀장)를 위한
콜드 이메일 + 팔로업 3단계 시퀀스 작성.

컨텍스트:
- 웨비나 "데이터 자동화 트렌드 2026" 참가자
- ERP SAP 사용, 수동 ETL이 Pain Point
- 직책: IT팀장 → 도입 권한 있지만 예산 결재는 임원

시퀀스:
Day 0: 콜드 이메일 (웨비나 참가 언급, 제조업 ETL 사례 포함)
Day 3: 팔로업 1 (SAP 연동 특화 자료 링크)
Day 7: 팔로업 2 (비슷한 제조업 사례 수치 공유)
Day 14: 팔로업 3 (마지막 시도, 정중히 close)

각 이메일: 제목 + 본문 (Day 0은 200자, 팔로업은 100자 이내) + 발송 이유 주석
```

### 실습 2-2. 이커머스 세그먼트 이메일 시퀀스

```
이커머스 세그먼트 (박수진 팀장, XYZ커머스 데이터분석팀)를 위한
시퀀스 작성. 위와 동일 구조.

컨텍스트:
- Zapier 사용 중 → 한계 도달 암시
- 실시간 재고 데이터 지연이 핵심 Pain Point
- 직책: 데이터분석팀장 → 기술 이해도 높음, 직접 평가 가능

Day 0: Zapier 한계 → CloudPipe 전환 사례 중심
Day 3: 실시간 데이터 아키텍처 비교 자료
Day 7: 이커머스 고객 성과 수치
Day 14: 무료 트라이얼 또는 데모 제안
```

### 실습 2-3. 스타트업 세그먼트 (빠른 전환 타겟)

```
스타트업 세그먼트 (강동원 CTO, 소프트빌더 / 전지현 CTO, 핀테크스타트업)를 위한
짧고 직접적인 시퀀스 작성.

컨텍스트:
- CTO = 의사결정 빠름, 기술 이해도 높음
- 스타트업 = 비용 민감, 빠른 ROI 중요
- 팀 규모 작음 → Starter 요금제 적합

이메일 톤: CTO 대 CTO 수준의 직접적인 언어 (과장 없이, 기술적 정확성 중요)

Day 0: 짧고 직접적 (150자), 기술적 Pain Point 직격
Day 7: 무료 트라이얼 직접 제안 (가격 명시)
Day 21: 마지막 시도 (짧게, 50자)
```

## Phase 3. 맞춤형 제안서 3종 (20분)

### 목표

세그먼트별로 각각 다른 제안서 초안을 만듭니다. 같은 제품이지만 업종에 따라 강조점이 달라집니다.

### 실습 3-1. 제조업 제안서 — ERP 연동 강조

```
ABC제조 (제조업, IT팀장 이민수) 대상 제안서 구조 + Executive Summary + 문제 정의 섹션 작성.

강조 포인트:
- SAP ERP ↔ CloudPipe 연동으로 데이터 자동 흐름
- 생산/품질 데이터를 실시간으로 분석
- 현장 데이터 오류 감소 + 보고서 자동화
- IT 팀의 반복 업무 제거 → 전략 업무 집중

사례 포함: 비슷한 규모 제조업 고객의 "ETL 자동화 3개월 후 70% 공수 절감" 가상 사례
(※ 실제 고객 데이터 없으므로 예시임을 명시)
```

### 실습 3-2. 금융 제안서 — 규제 준수 & 보안 강조

```
한빛금융 (금융, 디지털전환TF 최준호) 대상 제안서 핵심 섹션 작성.

강조 포인트:
- 레거시 코어뱅킹 시스템 ↔ 분석 도구 연동
- 금융감독원 보고 자동화 (정기 리포트)
- 데이터 암호화, 접근 제어, 감사 로그 (보안 기능)
- 국내 데이터 센터 운영 (해외 서버 데이터 이전 없음)
- 컴플라이언스: 개인정보보호법, 전자금융거래법 준수

섹션: Executive Summary + 문제 정의 + 보안/규제 대응 섹션 + 가격 옵션
```

### 실습 3-3. 이커머스 제안서 — 실시간 데이터 & 빠른 ROI 강조

```
XYZ커머스 (이커머스, 데이터분석팀장 박수진) 대상 제안서 핵심 섹션 작성.

강조 포인트:
- Zapier에서 CloudPipe로 전환 (마이그레이션 지원 포함)
- 실시간 재고 ↔ 주문 ↔ 광고 성과 데이터 통합 파이프라인
- 마케팅 ROI 분석 자동화
- 성수기(블랙프라이데이 등) 트래픽 급증 시 자동 스케일링

ROI 계산:
- 현재: 데이터분석팀장 + 팀원 2명, 하루 2시간 수동 데이터 정리
- CloudPipe 후: 자동화로 하루 10분으로 단축
- 연간 절감 시간, 인건비 환산
```

## Phase 4. 결과물 통합 & 검토 (10분)

### 목표

만들어진 결과물을 실제 발송 가능한 수준으로 검토하고, 문서화합니다.

### 실습 4-1. 이메일 품질 자가 검토

만들어진 이메일 시퀀스 중 하나를 골라 아래 체크리스트로 검토합니다.

```
아래 이메일을 품질 체크해줘.

체크 항목:
[ ] 제목이 30자 이내이며 클릭하고 싶은가?
[ ] 수신자 이름이 자연스럽게 포함되어 있는가?
[ ] 수신자의 Pain Point가 정확히 반영되어 있는가?
[ ] 영업 냄새를 풍기는 단어가 없는가? (혁신, 최고, 독보적 등)
[ ] CTA가 명확하고 부담이 없는가?
[ ] 길이가 적절한가? (Day 0: 200자 이내, 팔로업: 100자 이내)
[ ] 검토해야 할 수치나 사실이 있다면 표시했는가?

이메일:
[붙여넣기]

각 항목: 통과/수정필요 + 수정이 필요하면 개선 제안
```

### 실습 4-2. 제안서 검토 요청

```
만들어진 제안서 초안 중 하나의 Executive Summary를 검토해줘.

검토 관점:
1. 결론(ROI, 권장 요금제)이 첫 문단에 있는가?
2. 고객의 이름과 회사가 자연스럽게 녹아 있는가?
3. 수치가 구체적인가 (아니면 막연한가)?
4. 결정권자가 "이 제안을 검토해볼 만하다"고 느낄 문장이 있는가?
5. 어색하거나 영어 직역 같은 표현이 없는가?

[Executive Summary 붙여넣기]
```

## 팀 워크숍 운영 가이드 (강사용)

### 운영 방식

```
Phase 1 (10분): 개인 실습 → 결과 발표 (각 팀 1분)
Phase 2 (20분): 2인 1조 실습 → 완성본 공유 (Slack or 화면 공유)
Phase 3 (20분): 팀별 제안서 초안 발표 (각 3분)
Phase 4 (10분): 강사 데모 — "Copilot 없이 vs 있이" 속도 비교
```

### 토론 주제

1. "Copilot이 만든 이메일에서 어색한 부분이 있었나요? 어떻게 고쳤나요?"
2. "개인화 수준이 실제 업무에 쓸 수 있는 수준인가요?"

## 핵심 포인트 — Day 1 총정리

1. **영업 업무의 70%는 텍스트** — Copilot은 이 부분을 직접 담당
2. **개인화 = {{변수}} 시스템** + Copilot 배치 처리로 100명 → 30분
3. **좋은 이메일의 법칙**: 수신자 관찰 → Pain Point → 증거 → 부담 없는 CTA
4. **제안서의 핵심**: 고객 문제와 비용을 수치로, 솔루션을 결과 스토리로
5. **검토는 항상 사람이** — 수치, 사례, 회사명 등 반드시 검증 후 발송
