# 05. CS 응대 스크립트 & 매크로

## 학습 목표

- 상황별 CS 응대 매크로를 Copilot으로 신속하게 만드는 방법 체득
- 환불/배송지연/제품문의/컴플레인/이탈방지 5가지 핵심 상황 완전 커버
- 톤 조절(따뜻한/간결한/상세한)을 자유자재로 하는 방법 이해
- 오브젝션 처리와 에스컬레이션 기준 수립
- BAD vs GOOD 응대 3가지 비교로 고객 만족도 차이 체감

**예상 소요**: 60분 (실습 포함)

## 1부. CS 응대의 원칙

### 좋은 CS 응대의 3가지 요소

**1. 공감(Empathy) 먼저**
고객이 화났거나 실망했을 때, 정책 설명보다 먼저 감정을 인정해야 합니다. "불편하셨겠습니다"는 형식이 아니라 진심으로 쓰여야 합니다.

**2. 명확성(Clarity)**
다음 단계가 무엇인지, 기간이 얼마인지, 누가 처리하는지 — 고객이 이 이메일 하나로 상황을 파악할 수 있어야 합니다.

**3. 해결 지향(Solution Focus)**
"안 된다"로 끝나지 말고, 대안을 제시합니다. 100% 해결이 안 되더라도 가능한 범위의 대안이 있습니다.

### CS 응대 5단계 구조

```
1. 인사 + 감사 (1문장)
2. 공감/사과 (1~2문장)
3. 상황 설명/사유 (1~2문장, 선택)
4. 해결 방법 + 기간 (2~3문장, 핵심)
5. 추가 도움 + 담당자 정보 (1~2문장)
```

### 에스컬레이션 기준

모든 CS 문의를 혼자 처리하려 하면 안 됩니다. 아래 상황에서는 팀장이나 담당 부서로 즉시 에스컬레이션합니다.

```
즉시 에스컬레이션:
- 법적 분쟁 언급 ("소송", "신고", "환불청구권") 
- VIP/Enterprise 고객의 반복 컴플레인
- 서비스 장애로 인한 사업 피해 주장
- 개인정보 침해 의심

24시간 내 에스컬레이션:
- 동일 고객이 3회 이상 같은 문제 제기
- CSAT 1~2점 + 감정적 컴플레인
- 계약 해지 암시

팀장 보고 (다음 날):
- NPS 6 이하 고객의 이탈 신호
- 반복적인 동일 유형 문의 급증 (제품 버그 가능성)
```

## 2부. BAD vs GOOD 응대 비교

### 비교 1: 환불 거절 응대

**❌ BAD — 규정 나열식 거절**

```
박지영님,

안녕하세요. 고객지원팀입니다.

저희 환불 정책에 따르면 구매 후 7일이 지난 경우 환불이 불가합니다.
고객님의 구매일은 15일 전이므로 환불 정책 기간이 초과되었습니다.
따라서 환불이 어렵습니다.

감사합니다.

고객지원팀
```

**문제점**:
- 공감이 전혀 없음
- "따라서 어렵습니다"로 차갑게 마무리
- 대안 제시 없음
- 고객이 이 이메일을 받으면 화가 더 남

---

**✅ GOOD — 공감 + 대안 제시**

```
박지영님, 안녕하세요.

기대와 다른 경험을 하셨을 것 같아 정말 죄송합니다.
말씀 주신 환불 요청을 꼼꼼히 검토했는데요,
구매 후 15일이 경과되어 저희 정책상 직접 환불을 처리하기가 어려운 상황입니다.
(환불 가능 기간: 구매 후 7일 이내)

대신 두 가지 방법을 제안드릴게요:

**옵션 A**: 구매 금액 100% 서비스 크레딧으로 전환 (유효기간 1년)
**옵션 B**: 현재 요금제 교체 — 더 적합한 플랜으로 무료 전환

어떤 방법이 더 맞으시는지 알려주시면 바로 처리해드리겠습니다.
추가로 궁금하신 점이 있으시면 언제든 이 이메일로 회신 주세요.

김민준 / 고객경험팀 / cs@tangunsoft.com
```

**좋은 이유**:
- 공감이 먼저 (단순 형식이 아닌 구체적 공감)
- 정책 설명을 부드럽게 (규정 나열이 아닌 사실 전달)
- 실질적인 대안 2가지 제시
- 선택권을 고객에게

---

### 비교 2: 서비스 장애 사과

**❌ BAD — 기술적 변명 위주**

```
고객님,

저희 서비스에 기술적 문제가 발생하여 서비스 이용이 불가했습니다.
이는 데이터센터 네트워크 스위치 장비의 펌웨어 업그레이드 중
예상치 못한 라우팅 오류로 인한 것입니다.

현재는 복구가 완료되었으며 이후 이런 일이 없도록 하겠습니다.

감사합니다.
```

**문제점**:
- 기술 설명이 먼저, 사과가 뒤
- "네트워크 스위치 펌웨어 업그레이드" — 고객에게 의미 없는 정보
- "이런 일이 없도록" — 막연한 약속
- 보상 언급 없음

---

**✅ GOOD — 사과 → 원인 (간략) → 보상 → 재발방지**

```
이민수 차장님, 안녕하세요.

오늘 오전 11:00~14:00 서비스 접속이 중단된 점 깊이 사과드립니다.
귀사의 업무에 영향이 있으셨을 것 같아 정말 죄송합니다.

장애 원인: 외부 인프라 업체의 네트워크 작업 중 예상치 못한 오류 발생
복구 시각: 14:03 완료 확인

**조치 사항**:
- 이번 장애 시간 기준 서비스 이용료 1일치 크레딧 적립 (자동 처리 완료)
- 이중화 네트워크 구성으로 재발 방지 조치 — 이번 주 내 완료 예정

현재는 정상 운영 중이며, 추가 이상이 있으시면 즉시 연락 주세요.
장애로 인한 불편에 다시 한번 사과드립니다.

박서연 / 인프라팀 / ops@tangunsoft.com / 02-xxx-xxxx
```

### 비교 3: 이탈 징후 고객 응대

**❌ BAD — 영업 압박형 응대**

```
고객님,

최근 서비스 사용이 줄어든 것 같아 연락드립니다.
저희 서비스를 충분히 활용하고 계신지 걱정됩니다.

지금 바로 다시 시작하시면 특별 혜택을 드릴 수 있습니다.
이번 달 안에 로그인하시면 추가 기능을 무료로 드리겠습니다!

빨리 돌아오세요!

영업팀
```

**문제점**:
- 제목부터 영업 목적이 뻔히 드러남
- "빨리 돌아오세요!" — 고객을 물건 취급하는 표현
- 고객이 왜 사용을 줄였는지 전혀 관심 없음
- 혜택이 조건부(기간 안에 로그인)라 부담을 줌

---

**✅ GOOD — 진심 어린 관심**

```
박수진 팀장님, 안녕하세요.

요즘 바쁘실 것 같아 안부가 궁금했습니다.

최근 접속이 뜸하셔서 혹시 서비스 이용 중에 막히거나
불편한 부분이 있으신 건 아닌가 걱정이 됐습니다.
사용하시다가 기대했던 것과 다른 부분이 있으시다면
꼭 알려주세요 — 직접 도와드리고 싶습니다.

참고로 지난달에 이커머스 팀들이 많이 쓰시는
"실시간 재고 파이프라인 템플릿"이 새로 추가됐는데,
한 번 살펴보시면 도움이 되실 수 있을 것 같아요.

편하실 때 10분만 시간 주시면 현재 상황 들어보고 싶습니다.

김민준 / 고객성공팀 / csm@tangunsoft.com
```

## 3부. 상황별 응대 매크로 완성 가이드

### 매크로 구조 이해

매크로(Macro)는 반복적인 상황에 쓰는 응대 템플릿입니다. 변수 부분만 바꿔서 쓰는 방식입니다.

```
매크로 ID: MAC-001
사용 상황: 환불 요청 수락 (정책 기간 내)
톤: 따뜻하고 명확하게
변수: {{firstName}}, {{orderId}}, {{refundAmount}}, {{processingDays}}

---
{{firstName}}님, 안녕하세요.

환불 요청을 접수해드렸습니다.
주문 번호 {{orderId}}의 {{refundAmount}}원은
{{processingDays}}일 이내에 결제하신 카드로 환불 처리됩니다.

혹시 처리 상황이 궁금하시면 언제든 문의해 주세요.

[담당자명] / 고객경험팀
---
```

### 5가지 핵심 상황 매크로 프롬프트

**상황 1. 환불 수락 매크로**

```
CS 응대 매크로 작성.

상황: 고객의 환불 요청 수락 (정책 기간 내)
변수: {{firstName}}, {{orderId}}, {{refundAmount}}, {{processingDays}}, {{agentName}}

조건:
- 감사 인사 + 처리 안내 명확히
- 처리 기간과 방법 구체적으로
- 추가 문의 채널 포함
- 5문장 이내

버전 2개:
A. 일반 고객
B. VIP/Enterprise 고객 (더 개인적이고 따뜻하게)
```

**상황 2. 배송/납품 지연 사과 매크로**

```
CS 응대 매크로 작성.

상황: 서비스/납품 지연 사과
변수: {{firstName}}, {{originalDate}}, {{newDate}}, {{delayReason}}, {{compensation}}

조건:
- 사과 먼저 (변명 전에)
- 지연 사유 간략 (기술적 용어 최소화)
- 새 예정일 명확히
- 보상 제안 (크레딧 or 할인)
- 진행 상황 확인 방법 안내

버전 3개: 하루 지연 / 일주일 이상 지연 / 원인 불명 지연
```

**상황 3. 기술 문의 응대 매크로**

```
CS 응대 매크로 작성.

상황: 기능 사용법 문의
변수: {{firstName}}, {{inquiry}}, {{solution}}, {{helpLink}}, {{agentName}}

조건:
- 문의 감사 인사
- 해결책 단계별 (numbered list, 최대 5단계)
- 전문 용어 최소화
- 도움말 링크 포함
- 추가 문의 채널

버전 2개:
A. 즉시 해결 가능한 경우
B. 개발팀 확인 필요 (ETA 포함)
```

**상황 4. 컴플레인 접수 매크로**

```
CS 응대 매크로 작성.

상황: 강한 불만 컴플레인 첫 응대
변수: {{firstName}}, {{complaintSummary}}, {{agentName}}, {{escalationTime}}

조건:
- 감정 충분히 공감 (형식적 사과 아님)
- 컴플레인 내용 확인(re-state)으로 "들었다" 표현
- 해결 프로세스 명확히 (언제까지, 누가)
- 직접 연락 방법 제공
- 방어적 표현 절대 없이

에스컬레이션 기준:
- 법적 용어 언급 → 즉시 팀장 CC
- 24시간 내 2회 이상 동일 문제 → 에스컬레이션
```

**상황 5. 이탈 방지 매크로**

```
CS 응대 매크로 작성.

상황: 사용량 급감 고객 근황 확인 이메일
변수: {{firstName}}, {{lastActiveDate}}, {{newFeature}}, {{csmName}}

조건:
- 영업 목적 완전히 숨기고 진심 어린 안부로 시작
- 막히는 부분 있는지 물어보기 (도움 제안)
- 새 기능/업데이트 1~2개 자연스럽게 언급
- 가벼운 CTA (10분 콜, 또는 답장)
- 부담 완전히 제거 (관심 없어도 괜찮다는 여지)
```

## 4부. Copilot으로 응대 3가지 톤 생성

같은 상황에서 톤이 다른 3가지 버전을 만드는 것은 CS 팀에서 매우 유용한 기술입니다. 상황에 따라 따뜻하게 접근해야 할 때도 있고, 빠르고 명확하게 처리해야 할 때도 있습니다.

### 3가지 톤 정의

```
톤 1. Warm (따뜻한/공감적)
적합 상황: 고객이 감정적으로 힘든 상황, 장기 고객, VIP
특징: 고객 감정 충분히 인정, 조금 더 길게, 따뜻한 마무리

톤 2. Professional (간결한/프로페셔널)
적합 상황: 바쁜 비즈니스 고객, 단순 기술 문의
특징: 핵심만, 150자 이내, 단계별 명확하게

톤 3. Detailed (상세한/친절한)
적합 상황: 초보 사용자, 설명이 많이 필요한 경우
특징: 단계별 설명, 스크린샷/링크 자리, FAQ 링크 포함
```

### 3가지 톤 프롬프트 (즉시 사용용)

```
아래 CS 응대 이메일을 3가지 톤으로 각각 재작성해줘.

원본 응대 상황:
고객 박지영님이 "CloudPipe 파이프라인 실행이 갑자기 안 된다"는 문의를 보냄.
원인: API 키 만료 (3개월마다 갱신 필요).
해결: 설정 → API 키 → 재발급 후 파이프라인 재실행.

톤 1 (Warm): 고객이 당황했을 것에 충분히 공감, 단계별 친절하게
톤 2 (Professional): 핵심 해결책만, 100자 이내
톤 3 (Detailed): API 키 갱신 단계별 5스텝, 헬프 링크, 예방 팁 포함

각 버전 끝에:
- 이 톤이 맞는 상황: 한 줄
- 주의할 점: 한 줄
```

## 5부. 5가지 Copilot 프롬프트 — CS 실전

### 프롬프트 1. 컴플레인 분류 + 응대 전략

```
아래 CS 티켓을 분류하고 응대 전략을 제안해줘.

티켓 내용:
"지난 2주 동안 같은 오류가 3번 발생했어요. 매번 연락하면 '확인 중'이라고만 하고
아무 해결이 없어요. 이런 서비스를 계속 써야 할 이유를 모르겠어요."

분류:
1. 컴플레인 유형 (기술/서비스/응대 품질)
2. 감정 상태 (1~5: 매우 화남 / 보통 / 약한 불만)
3. 에스컬레이션 필요도 (즉시/24h내/팀장 보고)
4. 이탈 위험도 (높음/중간/낮음)

응대 전략:
1. 첫 응대 이메일 초안 (위 상황 반영)
2. 에스컬레이션 필요 시 내부 이메일 초안
3. 이 고객을 유지하기 위한 다음 단계 2~3가지
```

### 프롬프트 2. FAQ 응대 매크로 세트 생성


## 핵심 포인트

1. **공감 먼저** — 정책/기술 설명은 공감 뒤에. 순서가 전부입니다
2. **해결책 없는 거절은 없다** — 100% 거절도 대안 1~2개와 함께
3. **매크로 = 변수 + 템플릿** — 한 번 잘 만들면 상황에 맞게 빠르게 변형 가능
4. **3가지 톤 전략** — 상황에 따라 Warm/Professional/Detailed 선택
5. **에스컬레이션 기준을 미리** — 판단하는 데 쓰는 시간을 줄여야 더 많은 고객을 도울 수 있음
