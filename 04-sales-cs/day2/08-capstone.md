## 캡스톤 시나리오

### 배경

**상황**: Q3(7~9월)가 시작되었습니다. Q2 파이프라인을 점검해보니 다음과 같은 상황입니다.

```
Q2 결과:
- 목표: 클로즈 딜 15건, 총 매출 1.5억
- 실적: 클로즈 딜 9건, 총 매출 8,700만원 (목표 달성률 58%)
- 주요 이탈 이유: "예산 없음" 4건, "타 솔루션 선택" 3건, "내부 결정 지연" 2건

Q3 목표:
- 클로즈 딜 18건 (Q2 대비 +9건), 총 매출 1.8억
- 현재 파이프라인: 42건, 총 예상 금액 5.4억
- 신규 리드 필요: 최소 60건 (전환율 30% 가정)

팀 구성:
- 영업 담당자 3명 (김민준, 이수진, 박성호)
- CS/CSM 2명 (최지원, 강현우)
```

**미션**: Q3 파이프라인 리부트를 위해 아래 5단계 작업을 Copilot으로 완성합니다.

## Phase 1. 리드 세그먼트 분석 + 아웃리치 전략 (15분)

## Phase 2. 세일즈 시퀀스 5단계 완성 (15분)

### 2-1. 마스터 시퀀스 설계

```
프롬프트:
Q3 아웃바운드 영업용 5단계 이메일 시퀀스 설계.

타겟: 세그먼트 C (이커머스/SaaS/핀테크, Tech-Forward)
제품: CloudPipe (ETL 자동화 SaaS)
시퀀스 목표: 15분 데모 미팅 확보

각 단계:
Step 1 (Day 0): 콜드 이메일 — 기술적 Pain Point 직격
Step 2 (Day 3): 팔로업 — 관련 케이스 스터디 + 수치
Step 3 (Day 7): 가치 추가 — 업종 인사이트 (이커머스 데이터 트렌드)
Step 4 (Day 14): 마지막 이메일 — 데모 직접 제안 + 일정 2개 옵션
Step 5 (Day 21): "정중한 close" — 관심 없으면 괜찮다, 열린 문 남기기

각 단계:
- 발송 이유/목적 한 줄
- 제목 2개 옵션
- 본문 (Step 1: 200자, Step 2~4: 120자, Step 5: 80자)
- 핵심 CTA
```

### 2-2. 업종별 시퀀스 변형 3세트

```
프롬프트:
위 5단계 시퀀스를 3개 업종에 맞게 각각 변형.

버전 A: 이커머스 — 실시간 재고/주문 데이터 중심
버전 B: 금융/핀테크 — 규제 준수, 보안, 레거시 연동 중심
버전 C: 제조업 — ERP 연동, 생산 데이터, 품질 관리 중심

각 버전은 전체 시퀀스가 아닌 Step 1과 Step 3만 업종별로 재작성.
(Step 2/4/5는 공통 사용 가능)

각 버전: 제목 + 본문만. 길이 유지.
```

### 2-3. 팔로업 트리거 기반 분기 시퀀스

```
프롬프트:
이메일 응답 여부에 따라 분기되는 시퀀스 로직 설계.

분기 기준:
- 응답 O + 미팅 확정 → 데모 준비 이메일 (확인 + 사전 정보 요청)
- 응답 O + "나중에 연락주세요" → 30일 후 재접촉 이메일
- 응답 O + "관심 없음" → 정중한 close + 6개월 후 "제품 업데이트" 이메일 예약
- 응답 X, 5단계 완료 → 수신거부 확인 후 "분기별 인사이트" 뉴스레터 이동

각 분기별:
- 이메일 제목 + 본문 (80자 이내)
- 다음 액션 (CRM 업데이트, 팔로업 일정 등)

형식: 플로우차트 텍스트 + 각 이메일 초안
```

## Phase 3. CS 응대 매크로 세트 완성 (10분)

### 3-1. 팀 공용 매크로 라이브러리 (5개 상황 × 2가지 톤)

```
프롬프트:
아래 5가지 상황에 대해 각각 2가지 톤의 응대 매크로를 작성.
총 10개 매크로. 팀 라이브러리 형식으로.

상황 목록:
1. 환불 수락
2. 환불 거절 + 크레딧 대안
3. 서비스 장애 사과 + 보상
4. 기술 문의 (파이프라인 오류)
5. 이탈 위험 고객 근황 확인

각 상황별 톤:
- Warm (따뜻한/공감적): VIP/장기 고객용
- Professional (간결한): 바쁜 비즈니스 고객용

매크로 형식:
---
**매크로 ID**: MAC-XXX
**상황**: [한 줄]
**톤**: Warm / Professional
**변수**: {{변수명}} 목록
**이메일**:
[본문]
---
```

### 3-2. 에스컬레이션 의사결정 트리

```
프롬프트:
CS 에스컬레이션 의사결정 트리 작성.

입력: 컴플레인 티켓
출력: 에스컬레이션 수준 (즉시/24h/팀장보고/일반처리)

결정 기준 (if-then 형식):
- "법적 분쟁", "소송", "환불청구" → 즉시 에스컬레이션
- Enterprise 고객 + 반복 문의 (3회 이상) → 즉시
- 서비스 장애로 사업 피해 주장 → 즉시
- NPS 1~3 + 감정적 컴플레인 → 24시간 내
- 해지 암시 → 24시간 내
- 동일 유형 티켓 급증 (일 5건 이상) → 팀장 보고
- 그 외 일반 문의 → 일반 처리

형식: Markdown 결정 트리 (들여쓰기 방식) + 각 수준별 응대 초안 1개
```

## Phase 5. 미팅록 요약 자동화 (10분)

### 5-1. 고객 미팅 → 구조화된 회의록

```
프롬프트:
아래 영업 미팅 메모를 구조화된 회의록 + CRM 업데이트 지침으로 변환.

원본 메모 (예시):
"7/15 ABC제조 이민수 차장, 최정호 IT본부장 참석.
30분 미팅. CloudPipe 데모 진행.
차장은 SAP 연동에 관심. 본부장은 보안 데이터 국내 저장 여부 중요하다고.
가격은 Growth 89만원 부담스럽다. 10~15% 할인 가능한지 물어봄.
2주 안에 내부 검토 후 연락 예정. 데모 영상 녹화본 요청.
다음 단계: 데모 영상 + 보안 백서 + 할인 조건 내부 승인 요청."

회의록 구조:
1. 미팅 요약 (3문장)
2. 참석자
3. 고객 주요 발언 (불릿)
4. 발견된 니즈 + Pain Point
5. 반박/우려사항 + 우리 대응
6. 합의된 다음 단계 (표: 액션/담당/기한)
7. CRM 업데이트 지침 (단계, 확률, 메모)
8. 영업 기회 점수 (1~10) + 근거
```
