## Stage 1. Awareness

> 리드가 우리 제품을 처음 알게 되는 단계. 콜드 아웃리치, 인트로 이메일, LinkedIn 메시지.

### P-01. 콜드 이메일 기본형

```
B2B SaaS {{제품명}} 영업용 콜드 이메일 작성.

수신자 정보:
- 이름: {{firstName}} {{lastName}}
- 직책: {{jobTitle}}
- 회사: {{company}} (업종: {{industry}})
- 추정 Pain Point: {{painPoint}}

이메일 구조:
1. 제목: 클릭률 높은 제목 3가지 제안 (숫자 또는 질문 포함)
2. 본문 (150자 이내):
   - 오프닝: 수신자 관점의 공감 1문장
   - 핵심 가치: 우리 제품이 {{painPoint}}를 어떻게 해결하는지 1~2문장
   - CTA: 15분 미팅 제안 (구체적 날짜/시간 없이)
3. 서명: {{senderName}} / {{senderTitle}} / {{company}}

톤: 프로페셔널하되 딱딱하지 않게. 영업 냄새 최소화.
금지: 과장 표현, "혁신적", "최고의", "독보적" 같은 상투어
```

### P-02. 업종별 콜드 이메일 변형

```
위 콜드 이메일을 아래 3개 업종에 맞게 각각 변형해줘.
각 버전에서 업종 특유의 Pain Point와 용어를 반영할 것.

업종 A: 제조업 (생산/품질 관리 담당자)
업종 B: 이커머스 (데이터/마케팅 팀)
업종 C: 금융/보험 (IT 기획 또는 디지털 전환 담당)

각 버전: 제목 1개 + 본문 (150자 이내) + 업종별 차별 포인트 주석
```

### P-03. LinkedIn 인메일/연결 요청 메시지

```
LinkedIn 연결 요청 메시지 작성. 300자 이내.

내 정보: {{senderName}}, {{senderTitle}} at {{senderCompany}}
상대: {{firstName}}, {{recipientTitle}} at {{recipientCompany}}
공통점 또는 접점: {{commonGround}} (예: 같은 행사 참석, 공통 지인, 상대 포스팅 읽음)

메시지 방향:
- 판매 요청 없이, 진심 어린 네트워킹 제안
- 공통점을 자연스럽게 언급
- 부담 없는 마무리 (대화 나눠봐도 좋겠다 수준)
```

### P-04. 콜드 콜 오프닝 스크립트

```
콜드 콜 오프닝 스크립트 작성. 전화 받은 첫 30초용.

상황: {{firstName}}에게 처음 전화. {{company}}의 {{jobTitle}}.
제품: {{productName}}
핵심 메시지: {{keyMessage}}

스크립트 구성:
1. 자기소개 (5초)
2. 전화 이유 (5초, 가치 중심)
3. 허락 구하기 — "잠깐 말씀드려도 될까요?" (5초)
4. 관심 확인용 질문 1개 (10초)

톤: 자신 있되 강요하지 않음. 상대를 불편하게 만들지 않음.
버전 2개 제공: 결정권자 직접 연결 버전 / 게이트키퍼 통과 버전
```

### P-05. 이벤트/웨비나 후 팔로업 이메일

```
웨비나/이벤트 참가자 대상 팔로업 이메일 작성.

이벤트: {{eventName}} ({{eventDate}})
수신자: {{firstName}}, {{company}}
공유할 내용: 이벤트 자료 링크, 관련 케이스 스터디 1개
CTA: 30분 데모 신청 링크

조건:
- 이메일 길이: 200자 이내
- 발송 타이밍 언급: "어제 {{eventName}} 에서 뵈었는데..."로 시작
- 자료 링크는 {{materialLink}} 변수로 처리
- 과도한 영업 피치 없이, 가치 제공 위주
```

### P-06. 소개/레퍼럴 이메일

```
기존 고객 {{referrerName}}이 소개해준 신규 리드 {{firstName}}에게 보내는 첫 이메일.

포함 요소:
- {{referrerName}} 언급 (자연스럽게, 첫 문장 또는 둘째 문장)
- 소개받은 계기 언급: {{referralContext}}
- 간단한 자기소개와 우리 제품의 핵심 가치 1줄
- CTA: 짧은 인트로 콜 제안

톤: 따뜻하되 프로페셔널. 소개받은 덕에 부담을 주지 않는 느낌.
```

### P-07. 경쟁사 사용 고객 대상 접근 이메일

```
현재 경쟁사 {{competitorName}} 제품을 쓰고 있는 것으로 추정되는 고객에게 보내는 이메일.

우리 제품의 차별점 (경쟁사 대비): {{differentiator}}
타겟 Pain Point (경쟁사 한계): {{competitorWeakness}}

조건:
- 경쟁사를 직접 비방하지 않음 (간접 비교만)
- "혹시 이런 불편함 느끼신 적 없으신가요?" 방식으로 Pain Point 건드리기
- 무료 비교 데모 또는 비용 절감 계산기 CTA 포함
- 제목 3가지 옵션
```

## Stage 2. Consideration

> 리드가 관심을 보이고 검토 중인 단계. 팔로업, 제안서, 케이스 스터디, 데모 후 요약.

### P-08. 3단계 팔로업 시퀀스

```
콜드 이메일 발송 후 응답 없는 리드에게 보내는 팔로업 3단계 시퀀스 작성.

리드 정보:
- {{firstName}}, {{company}}, {{jobTitle}}
- 첫 이메일 발송일: {{initialEmailDate}}
- 첫 이메일 핵심 내용: {{initialEmailSummary}}

각 단계별 발송 간격과 톤:
- Day 3: 가볍게 확인 (첫 이메일 리마인드 + 새 정보 1개)
- Day 7: 가치 추가 (케이스 스터디 or 업종 인사이트 공유)
- Day 14: 마지막 시도 (정중하게 close — 관심 없으면 말씀해달라)

각 이메일: 제목 + 본문 (100자 이내) + CTA
```

### P-09. 데모 미팅 후 요약 이메일

```
30분 데모 미팅 후 발송하는 요약/다음 단계 이메일 작성.

미팅 정보:
- 참석자: {{attendees}}
- 날짜: {{meetingDate}}
- 논의 내용 요약: {{meetingSummary}}
- 고객이 관심 보인 기능: {{keyInterests}}
- 고객이 언급한 우려사항: {{concerns}}
- 합의한 다음 단계: {{nextSteps}}

이메일 구조:
1. 감사 인사 (1문장)
2. 미팅 요약 (불릿 3~5개)
3. 고객 관심사에 맞춘 추가 자료 링크 {{resourceLinks}}
4. 우려사항 간략 대응 (있는 경우)
5. 다음 단계 명확히 (날짜/담당자 포함)

톤: 친근하고 실무적. 영업 압박 없이.
```

### P-10. 케이스 스터디 요약 이메일

```
비슷한 업종의 성공 사례를 리드에게 공유하는 이메일 작성.

수신자: {{firstName}}, {{company}} (업종: {{industry}})
사례 회사: {{caseCompany}} (업종: {{caseIndustry}})
성과 지표: {{metrics}} (예: "도입 3개월 만에 데이터 처리 시간 70% 단축")
관련 기능: {{relevantFeature}}

이메일 구조:
1. 제목: 성과 숫자 포함
2. 본문: "{{firstName}}님 회사와 비슷한 상황이라 공유드립니다" → 사례 요약 2~3문장
3. 풀 케이스 스터디 링크 {{caseLink}}
4. CTA: "이런 결과, {{company}}에서도 가능한지 15분 이야기 나눠보실래요?"
```

### P-11. 제안서 커버 레터

```
제안서에 첨부할 커버 레터 작성.

수신자: {{firstName}} {{lastName}}, {{jobTitle}}, {{company}}
제안 날짜: {{proposalDate}}
제안 배경: {{context}} (예: 지난주 미팅에서 논의한 내용 기반)
핵심 제안 요약: {{proposalSummary}}
예상 효과: {{expectedOutcome}}
발신자: {{senderName}}, {{senderTitle}}, {{senderCompany}}

커버 레터 조건:
- A4 반 페이지 이내
- 고객 이름과 상황을 자연스럽게 녹임
- 제안서 본문으로 유도하는 마무리
- 포멀하되 딱딱하지 않은 톤
```

### P-12. 가격 문의 응대 이메일

```
고객이 가격을 문의했을 때 보내는 이메일.

고객 정보: {{firstName}}, {{company}}
문의 내용: {{inquiry}}
현재 요금제 구조:
  - Starter: {{starterPrice}} / {{starterFeatures}}
  - Growth: {{growthPrice}} / {{growthFeatures}}
  - Enterprise: 별도 협의

이메일 목적:
- 가격표 공유하되, 바로 숫자만 던지지 않기
- 고객 규모/상황에 맞는 요금제 추천
- ROI 관점 설명 추가 (가격 대비 절감 효과)
- 다음 단계: 정확한 견적을 위한 짧은 콜 제안

톤: 투명하고 정직하게. 가격 숨기거나 회피하지 않음.
```

### P-13. 비교 분석 표 작성

```
우리 제품 {{productName}}과 경쟁사 {{competitor1}}, {{competitor2}} 비교 표 작성.

비교 항목:
1. 가격 (월정액 기준)
2. 주요 기능 A: {{featureA}}
3. 주요 기능 B: {{featureB}}
4. 온보딩/지원 방식
5. 계약 조건 (연간/월간, 최소 약정)
6. 한국어 지원 여부
7. 데이터 보안/컴플라이언스

형식: Markdown 표. 우리 제품이 우위인 항목에 ✅ 표시.
주의: 경쟁사 정보는 공개된 사실만 (과장 없이). 추정치는 "~추정" 주석.
```

### P-14. 오브젝션(반박) 처리 응답 시트

```
영업 미팅에서 자주 나오는 오브젝션 {{objection}}에 대한 응답 작성.

오브젝션 유형별 응답 (각각):
1. "지금 예산이 없어요" → 응답: ROI 관점 + 분기 내 시작 방법
2. "현재 쓰는 솔루션이 있어요" → 응답: 전환 비용 최소화 + 병행 운영 제안
3. "내부 검토가 필요해요" → 응답: 의사결정자 포함 미팅 제안 + 검토 자료 패키지
4. "너무 복잡할 것 같아요" → 응답: 온보딩 기간 + 성공 사례 수치
5. "경쟁사가 더 저렴해요" → 응답: TCO(총 소유 비용) 비교 + 지원 품질 차이

각 응답: 2~3문장. 논쟁이 아닌 공감 → 정보 제공 → 다음 단계 제안 구조.
```

### P-15. RFP(제안 요청서) 응답 초안

```
고객사 RFP에 응답하는 제안서 초안 작성.

RFP 핵심 요구사항:
{{rfpRequirements}}

우리 회사 강점:
- {{strength1}}
- {{strength2}}
- {{strength3}}

제안서 구조:
1. 요약 (Executive Summary) — 1페이지
2. 고객 이해 — 문제/니즈 재해석
3. 솔루션 제안 — 요구사항별 대응 방안
4. 구현 일정 — 마일스톤 4~6단계
5. 가격 제안 — 요금제별 옵션 + 볼륨 할인
6. 레퍼런스 — 유사 사례 3개
7. 팀 소개 — 핵심 인력 약력

분량: 섹션별 개요 수준. 실제 내용은 별도 입력 후 확장.
```

## Stage 3. Decision

> 구매 결정 단계. 계약서 초안, 최종 제안, 할인 협상, 온보딩 준비.

### P-16. 최종 제안 이메일 (Closing)

```
구매 결정을 앞둔 고객에게 보내는 최종 제안 이메일 작성.

고객: {{firstName}}, {{company}}
지금까지 진행 상황: {{dealHistory}}
최종 제안 내용: {{finalOffer}}
유효 기간: {{expiryDate}}
포함 혜택: {{incentive}} (예: 2개월 무료, 무료 온보딩, 전담 CSM)

이메일 목적:
- 지금까지의 여정에 감사
- 최종 제안 명확하게 요약
- 유효 기간 언급 (압박 없이 자연스럽게)
- CTA: 계약서 검토 링크 or 서명 요청

금지: 고압적 마감 압박. "이번 주 안에 결정 안 하시면..." 식 표현 절대 금지.
```

### P-17. 계약서 초안 요청 이메일 (내부용)

```
법무/계약 팀에 계약서 초안 작성을 요청하는 내부 이메일 작성.

계약 상대: {{clientCompany}}
계약 종류: {{contractType}} (예: SaaS 이용 계약, NDA, MSA)
계약 주요 조건:
  - 계약 기간: {{term}}
  - 금액: {{amount}}
  - 결제 방식: {{paymentTerms}}
  - 특이 사항: {{specialTerms}}
필요 시점: {{deadline}}
담당 영업: {{salesRep}}

톤: 내부 이메일. 친근하되 필요 정보 빠짐없이.
```

### P-18. 할인 요청 처리 이메일

```
고객이 할인을 요청했을 때 응대하는 이메일 작성.

고객: {{firstName}}, {{company}}
요청 할인율: {{requestedDiscount}}
우리가 제공 가능한 조건: {{availableDiscount}}
조건: {{discountCondition}} (예: 연간 선불 결제, 2년 약정 등)

이메일 방향:
- 요청을 진지하게 받아들이는 태도
- 가능한 범위 내에서 대안 제시 (직접 할인 아닌 가치 추가 옵션도 포함)
- 조건부 할인 제안 (계약 조건 변경 시)
- 결정권자 확인 필요 시 내부 승인 프로세스 언급

톤: 유연하되 우리 입장도 명확히. 무조건 양보 인상 주지 않기.
```

### P-19. 온보딩 킥오프 이메일

```
계약 체결 후 온보딩 시작을 알리는 이메일 작성.

신규 고객: {{firstName}}, {{company}}
계약 시작일: {{startDate}}
담당 CSM: {{csmName}}
온보딩 일정: {{onboardingSchedule}}
첫 미팅 일시: {{firstMeetingDate}}

이메일 포함 내용:
1. 계약 체결 축하 및 환영 인사
2. 온보딩 프로세스 간략 소개 (3~4단계)
3. 첫 미팅 일정 확인
4. 사전 준비 사항 (있다면): {{preMeetingTasks}}
5. 담당 CSM 소개 + 연락처

톤: 따뜻하고 기대감 주는 어조. 고객이 좋은 선택을 했다는 확신 심어주기.
```

### P-20. 계약 갱신 제안 이메일

```
계약 만료 60일 전 갱신 제안 이메일 작성.

고객: {{firstName}}, {{company}}
현재 계약 만료일: {{expiryDate}}
```
