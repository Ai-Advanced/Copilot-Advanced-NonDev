# 01. HR의 하루와 Copilot — 15가지 활용 시나리오

## 학습 목표

- HR 담당자의 실제 하루 업무에서 Copilot이 어디에 끼어드는지 파악
- Before/After 비교로 시간 절감 효과를 구체적으로 체감
- HR 특유의 개인정보·편향 주의사항을 내면화

**예상 소요**: 40분 (실습 포함)

---

## 1.1 HR 담당자의 하루 — 문서가 끊이지 않는 이유

HRBP 김지은 씨의 어제 업무 목록입니다 (실제 HR 담당자 인터뷰 기반, 가상 인물).

```
오전
09:00  어제 접수된 이력서 12건 검토 (신규 포지션 2개)
10:00  채용 공고 JD 수정 요청 — "좀 더 매력적으로 써달라"
11:00  신규 입사자 A씨 온보딩 체크리스트 업데이트
11:30  팀장 B씨와 조직 진단 서베이 결과 공유 회의

오후
13:00  분기 성과 리뷰 템플릿 배포 준비
14:00  인터뷰 가이드 신규 작성 (시니어 PM 포지션)
15:30  퇴직 예정자 C씨 Exit Interview 준비
16:00  연봉 협상 데이터 정리 (엑셀)
17:00  내일 신규 입사자 D씨 웰컴 이메일 발송
```

이 중에서 **"문서를 쓰거나, 데이터를 정리하거나, 템플릿을 만드는 일"**이 몇 가지인지 세어보세요. 대부분입니다. Copilot은 바로 이 반복적인 문서 작업에서 가장 강력합니다.

## 1.2 HR Copilot 15가지 활용 시나리오

### 채용 (Recruiting)

**1. JD 초안 생성**
역할명과 핵심 요구사항만 주면 구조화된 JD 초안이 나옵니다. 이후 편향 검토와 내부 검토를 거쳐 최종본 완성.

**2. 편향 언어 검출 및 수정**
작성한 JD나 공고에서 성별·연령·학력·외모 편향 표현을 자동으로 찾고 대안을 제시합니다.

**3. 채용 공고 SNS 요약**
500자짜리 JD를 LinkedIn용 300자, 인스타용 80자로 즉시 요약합니다.

**4. 이력서 스크리닝 매트릭스 설계**
역할의 Must-have 역량 기준으로 평가표 구조를 잡아줍니다. 사람이 스크리닝에 쓰는 기준을 명확히 하는 데 도움이 됩니다.

**5. 인터뷰 질문 세트 생성**
역할별 BEI 질문 20개 + 평가 루브릭을 10분 만에 생성합니다.

**6. 오퍼 레터 초안**
환영 톤을 살리면서 필수 법적 고지가 빠지지 않도록 초안을 잡아줍니다.

**7. 채용 거절 이메일 (서류/면접 후)**
단계별로 다른 톤의 거절 이메일을 3가지 버전으로 한 번에 만들어줍니다.

### 온보딩 (Onboarding)

**8. 역할별 90일 온보딩 플랜**
역할 특성에 맞는 30/60/90일 목표와 체크리스트를 구조화합니다.

**9. 웰컴 이메일 + 첫날 안내**
신규 입사자가 첫날 느끼는 불안을 줄이는 구체적 이메일을 생성합니다.

**10. 온보딩 FAQ 문서**
반복되는 신규 입사자 질문을 모아 FAQ 형태로 정리합니다.

### 인사 평가 (Performance)

**11. 성과 리뷰 템플릿**
SMART 목표, STAR 구조 서술, 개선 영역 서술 가이드를 포함한 리뷰 문서를 잡아줍니다.

**12. 360도 피드백 문항 설계**
관리자/동료/부하/셀프 각각 다른 문항을 역할에 맞게 생성합니다.

### HR 데이터 (Data)

**13. 엑셀 수식 생성**
근속연수 계산, 급여밴드 분류, 연차 잔여일 계산 수식을 즉시 만들어줍니다.

**14. 서베이 결과 요약**
집계된 서베이 데이터를 경영진 보고용 Markdown 리포트로 변환합니다.

### 정책·문화 (Policy & Culture)

**15. HR 정책 문서 초안**
재택근무 정책, 육아휴직 가이드, 교육비 지원 정책 등 근로기준법 근거와 함께 초안을 잡아줍니다.

## 1.3 Before/After — 3가지 실제 비교

### Before/After 1. JD 작성

**상황**: 시니어 데이터 분석가 포지션 신규 오픈. 채용 담당자 이하나 씨가 JD를 써야 합니다.

**Before (Copilot 없이)**
```
1. 기존 유사 JD 검색 (내부 드라이브 + 잡코리아 벤치마킹): 20분
2. 역할 내용 채용팀장과 슬랙으로 확인: 10분
3. 직접 초안 작성 (구조 잡고, 표현 고민하면서): 60분
4. 팀장 검토 후 수정 1회: 20분
총 소요: 약 110분
```

**After (Copilot 활용)**
```
1. 채용팀장과 슬랙으로 역할 확인: 10분
2. Copilot에 프롬프트 입력 (역할, 요구 역량, 회사 특성): 2분
3. 초안 검토 + 편향 검토 프롬프트 실행: 10분
4. 팀장 검토 후 수정: 10분
총 소요: 약 32분 (71% 단축)
```

**핵심 차이**: Copilot이 구조와 표현을 잡아주고, 이하나 씨는 내용의 정확성과 편향 여부에 집중했습니다.

---

### Before/After 2. 온보딩 체크리스트

**상황**: 신규 마케팅 팀장이 다음 주 입사. HRBP 박성민 씨가 온보딩 플랜을 준비해야 합니다.

**Before (Copilot 없이)**
```
1. 이전 마케터 온보딩 문서 찾기 (어디 있는지 모름): 15분
2. 발견한 문서가 2년 전 것이라 역할에 안 맞음
3. 처음부터 재작성: 90분
4. 마케팅팀장과 내용 확인: 20분
총 소요: 약 125분
```

**After (Copilot 활용)**
```
1. Copilot에 역할·팀 규모·주요 도구 정보 입력: 3분
2. 90일 온보딩 플랜 초안 생성: 2분
3. 박성민 씨가 회사 특이사항 수정 (IT 계정, 슬랙 채널 등): 15분
4. 마케팅팀장 확인: 10분
총 소요: 약 30분 (76% 단축)
```

---

### Before/After 3. 인터뷰 질문 세트

**상황**: 프론트엔드 개발자 채용을 위한 기술 면접. HR이 기술 면접관 옆에서 행동 면접을 진행해야 합니다.

**Before (Copilot 없이)**
```
1. 행동 면접 질문 인터넷 검색: 20분
2. 찾은 질문들이 개발자에게 맞지 않아 커스터마이징: 40분
3. 평가 기준 직접 작성: 30분
총 소요: 약 90분
```

**After (Copilot 활용)**
```
1. Copilot에 "프론트엔드 개발자 BEI 질문 20개 + 루브릭" 프롬프트 입력: 2분
2. 결과 검토 및 회사 맥락에 맞게 수정: 15분
3. 면접관과 공유 전 편향 질문 여부 확인: 5분
총 소요: 약 22분 (76% 단축)
```

## 1.4 HR 특유의 개인정보·편향 주의사항

HR 업무는 다른 직군보다 **개인정보와 편향** 두 가지에 훨씬 더 민감합니다. Copilot을 쓸 때도 이 두 가지를 항상 의식해야 합니다.

### 개인정보보호법 관련 주의사항

**원칙**: 실제 직원·지원자의 식별 가능한 정보를 Copilot 프롬프트에 입력하지 않습니다.

| 입력하면 안 되는 정보 | 대신 쓰는 방법 |
|----------------------|----------------|
| 실명 (김OO, 박OO 등) | "지원자 A", "직원 B" |
| 주민등록번호 | 제외 |
| 전화번호·이메일 주소 | 제외 |
| 실제 연봉 금액 | "[AMOUNT]" 자리표시자 또는 범위로 |
| 구체적 성과 수치 (내부 기밀) | 익명화된 퍼센트/배수로 |
| 건강 정보 | 제외 |

**개인정보보호법 핵심 조항 (HR 관련)**
- 제15조: 수집 목적 외 사용 금지
- 제17조: 제3자(AI 서비스 포함) 제공 시 동의 필요
- 제23조: 민감정보(건강, 종교 등) 처리 제한
- 제24조: 고유식별정보(주민번호 등) 처리 제한

> **실무 팁**: 회사가 GitHub Copilot Business/Enterprise를 사용하는 경우, 데이터 정책을 IT팀·법무팀에 먼저 확인하세요. 개인 라이선스와 데이터 보존 정책이 다를 수 있습니다.

### 채용절차법·근로기준법 — 물어보면 안 되는 것들

채용 과정에서 아래 항목을 묻거나 JD에 명시하면 법적 문제가 됩니다. Copilot이 생성한 JD나 인터뷰 질문에도 이런 표현이 섞일 수 있으니 반드시 검토하세요.

**채용절차법 제4조의3 (직무 수행과 무관한 개인정보 수집 금지)**

| 금지 항목 | 해당하는 표현 예시 |
|-----------|-------------------|
| 구직자의 용모·키·체중 등 신체적 조건 | "단정한 외모", "체력이 강한 분" |
| 출신 지역·혼인 여부·재산 | "수도권 거주 우대", "결혼 계획이 없는 분" |
| 직계 존비속 및 형제자매의 학력·직업·재산 | "부모님이 뭐 하시는지" |
| 이 법에서 정한 것 외의 신체 조건 관련 사항 | |

**근로기준법 제6조 (균등 처우 원칙)**
- 성별, 국적, 신앙, 사회적 신분에 따른 차별 금지
- 동일 가치 노동에 대한 동일 임금 원칙

**고용상 연령차별금지법**
- 합리적 이유 없이 연령을 이유로 한 차별 금지
- JD에 "신입 우대" 또는 "경력 10년 이상" 같은 표현도 맥락에 따라 간접 차별이 될 수 있음

### 편향(Bias) 주의사항

Copilot은 학습 데이터에 담긴 편향을 그대로 반영할 수 있습니다. 특히:

**젠더 편향**: 리더십 역할 JD에 남성적 표현("강하고 추진력 있는"), 돌봄 역할 JD에 여성적 표현("부드럽고 세심한")이 자동으로 나올 수 있습니다.

**학력 편향**: "우수한 학업 성적", "상위권 대학"을 자격 요건으로 넣는 경향이 있습니다. 대부분의 역할에서 이는 직무 연관성이 없습니다.

**연령 편향**: "활기찬", "젊은 마인드", "디지털 네이티브" 같은 표현이 나이에 대한 가정을 담습니다.

**대응 방법**: JD나 인터뷰 질문을 Copilot으로 만든 뒤, 반드시 **P-04 편향 검토 프롬프트**를 별도로 실행하세요.

## 1.5 Copilot을 HR 업무에 통합하는 방법

### VS Code에서 HR 문서 작업하기

HR 담당자 대부분은 Word나 Google Docs를 쓰지만, Copilot을 쓰려면 VS Code가 가장 효율적입니다.

**HR에서 자주 만드는 파일 형식**

| 파일 형식 | HR 용도 | VS Code 활용 |
|-----------|---------|--------------|
| `.md` | JD, 온보딩 문서, 정책, 가이드 | Copilot이 가장 잘 다루는 형식 |
| `.csv` | 직원 데이터, 서베이 집계 | Rainbow CSV 확장으로 보기 편하게 |
| `.xlsx` | 급여밴드, 근속 계산, 대시보드 | 수식 생성 후 엑셀에 붙여넣기 |
| `.js` | Apps Script 자동화 | 서베이·이메일 자동화 스크립트 |

**워크플로우 권장**

```
1. VS Code에서 .md 파일 새로 만들기
   (예: jd-backend-senior-20260720.md)

2. Copilot Chat에 프롬프트 입력
   → 결과를 파일에 붙여넣기

3. 편향 검토 프롬프트 실행
   → 수정

4. Markdown Preview (Ctrl+K V)로 미리보기

5. 최종본을 Notion / 채용 시스템에 복사
```

## 실습

### 실습 1. 내 업무의 Copilot 기회 목록 만들기 (10분)

`my-hr-copilot-list.md` 파일을 새로 만들고 아래 형식으로 채워보세요.

```markdown
# 내 업무 Copilot 기회 목록

## 매주 반복하는 문서 작업
1. [작업명]: [현재 소요 시간] → Copilot으로 절약 가능한 시간 예상
2.
3.

## 가장 시간이 많이 걸리는 채용 관련 작업
1.
2.

## 만들어두면 팀에 도움이 될 템플릿
1.
2.
```

### 실습 2. HR Copilot 첫 번째 프롬프트 (10분)

Copilot Chat에 아래 프롬프트를 그대로 입력해보세요.

```
HR 담당자가 신규 포지션 채용을 시작할 때 필요한 체크리스트 작성.

항목 15개. 채용 단계별 구분:
1. 채용 기획 단계 (5개)
2. JD 작성 및 공고 단계 (5개)
3. 전형 진행 단계 (5개)

각 항목: 담당자 | 기한 | 완료 여부 컬럼 포함.
출력: Markdown 표.
```

결과를 확인하고, 한 가지 항목이 마음에 들지 않으면 Chat에 계속해서 수정을 요청해보세요.

### 실습 3. Before/After 기록 (5분)

실습 2에서 직접 만들어본 체크리스트를 참고하여, 이 작업을 Copilot 없이 했다면 얼마나 걸렸을지 솔직하게 적어보세요.

```markdown
## My Before/After

작업: 채용 킥오프 체크리스트
Before (직접 작성): __ 분
After (Copilot 활용): __ 분
절감 시간: __ 분 (__ %)

느낀 점:
```

## 핵심 포인트

1. HR 업무의 70% 이상이 문서 집약적 — Copilot은 이 부분을 집중적으로 지원
2. **개인정보보호법**: 실제 직원/지원자 식별 정보를 프롬프트에 넣지 않기
3. **채용절차법**: AI가 만든 JD·인터뷰 질문에도 금지 항목이 들어갈 수 있음 — 편향 검토 필수
4. AI는 초안, **최종 판단은 반드시 사람이** — 채용 결정에 AI 출력을 그대로 쓰지 않기
5. VS Code + `.md` 파일 조합이 HR 문서 작업에 가장 효율적
