# 02. JD(Job Description) 작성 — 편향 없이, 매력 있게

## 학습 목표

- 좋은 JD의 6가지 구조를 이해하고 Copilot으로 즉시 생성
- 성별·연령·학벌·외모 편향 언어를 탐지하고 수정
- 스타트업 vs 대기업, 개발자 vs 마케터 JD의 차이를 반영한 초안 작성
- 한국 채용절차법·근로기준법 기준에서 위반 소지 제거

**예상 소요**: 60분 (실습 포함)

---

## 2.1 좋은 JD란 무엇인가

### JD가 하는 일

JD는 단순한 "구인 공고"가 아닙니다. JD는 동시에 세 가지 역할을 합니다.

1. **필터**: 자격 없는 지원자가 지원하지 않도록
2. **어필**: 맞는 사람이 지원하고 싶게 만들기
3. **계약의 씨앗**: 입사 후 역할 기대치의 기준이 됨

나쁜 JD는 자격 있는 사람을 걸러내고, 맞지 않는 사람을 끌어들입니다. 편향된 언어는 그 필터를 성별·연령·학력 기준으로 틀어버립니다.

### 좋은 JD의 6가지 구조

| 섹션 | 목적 | 권장 길이 |
|------|------|-----------|
| **1. 포지션 소개** | 왜 이 역할이 존재하는가, 무엇이 기대되는가 | 3~5문장 |
| **2. 주요 업무** | 실제로 매일 하는 일 (동사로 시작) | 불릿 6~8개 |
| **3. 자격 요건** | Must-have만. 없으면 채용 불가한 것 | 불릿 4~6개 |
| **4. 우대 사항** | Nice-to-have. 있으면 좋지만 필수 아님 | 불릿 2~4개 |
| **5. 우리 팀 소개** | 팀 문화, 일하는 방식, 규모 | 2~3문장 |
| **6. 성장 기회** | 이 역할에서 어떻게 성장할 수 있는지 | 2~3문장 |

**자주 하는 실수**: 자격 요건에 Must-have와 Nice-to-have를 섞어 놓는 것. 자격 요건이 길어질수록 특히 여성 지원자가 "모든 요건을 충족해야 지원할 수 있다"고 느끼는 경향이 연구로 확인되었습니다 (Gaucher et al., 2011). 자격 요건은 짧게, 우대 사항으로 분리하세요.

## 2.2 편향 언어 — 유형과 실제 예시

### 유형 1. 젠더 편향 언어

젠더 편향 언어는 특정 성별이 해당 역할에 더 잘 맞는다는 무의식적 신호를 줍니다.

**남성 코딩 언어 (기술/리더십 JD에 많음)**

| 편향 표현 | 문제점 | 대체 표현 |
|-----------|--------|-----------|
| "강하게 추진하는" | 공격성 연상, 남성 편향 | "주도적으로 실행하는" |
| "싸워서 이기는" | 전투적 표현 | "목표를 집요하게 달성하는" |
| "독립적으로 움직이는" | 협업 배제 인식 | "자율적으로 판단하고 실행하는" |
| "지배적인 시장 점유" | "지배"의 공격성 | "시장 선도적인" |

**여성 코딩 언어 (HR/서비스 JD에 많음)**

| 편향 표현 | 문제점 | 대체 표현 |
|-----------|--------|-----------|
| "부드럽고 세심하게" | 여성 고정관념 | "섬세하고 체계적으로" |
| "양육하는 자세로" | 젠더 역할 고정 | "팀원의 성장을 지원하는" |
| "친화력이 좋은" | 여성 역할 기대 | "관계 구축에 능한" |

### 유형 2. 연령 편향 언어

| 편향 표현 | 문제점 | 대체 표현 |
|-----------|--------|-----------|
| "젊고 패기 있는" | 고용상 연령차별금지법 위반 소지 | "주도적이고 도전 지향적인" |
| "디지털 네이티브" | 젊은 세대 한정 의미 | "디지털 툴에 익숙한" |
| "경력 15년 이상의 베테랑" | 나이 간접 명시 | "해당 도메인 심층 전문성 보유" |
| "신선한 시각" | 젊음 선호 | "새로운 관점을 가져올 수 있는" |

### 유형 3. 학력·출신 편향

| 편향 표현 | 문제점 | 대체 표현 |
|-----------|--------|-----------|
| "명문대 졸업" | 학벌 차별 | (삭제, 또는 해당 전공 명시) |
| "SKY 이상 우대" | 명백한 학력 차별 | (삭제) |
| "어학연수 경험자" | 경제적 배경 차별 | "영어 비즈니스 커뮤니케이션 가능" |

### 유형 4. 신체·외모 편향

| 편향 표현 | 문제점 | 대체 표현 |
|-----------|--------|-----------|
| "단정한 외모" | 채용절차법 위반 | (삭제) |
| "건강한 체력" | 신체 조건 명시 | 실제 업무 요구(현장 이동, 장시간 서서 근무 등)를 구체적으로 서술 |
| "활동적인 외모" | 외모 차별 | (삭제) |

### 유형 5. 불필요한 자격 요건

| 편향 표현 | 문제점 | 대체 |
|-----------|--------|------|
| "4년제 대졸 이상" | 학력 차별, 직무 무관 | "관련 분야 지식 보유 (학력 무관)" |
| "차량 보유자" | 재산 조건 | "운전 가능 여부" 또는 삭제 |
| "군필 또는 면제자" | 성별 차별 (사실상 남성만 해당) | (삭제) — 병역은 별도 인사 절차로 확인 |

## 2.3 산업별·직군별 JD 차이

### 스타트업 JD vs 대기업 JD

| 항목 | 스타트업 | 대기업 |
|------|---------|--------|
| 톤 | 비격식, 구어체 허용 | 격식, 문어체 |
| 길이 | 짧고 임팩트 (300~500자) | 상세 (600~1000자) |
| 자격 요건 | 역량 중심, 학력 덜 강조 | 학력·자격증 명시 경향 |
| 복리후생 | 스톡옵션, 자율 재택 강조 | 4대보험, 연차, 교육비 강조 |
| 성장 언어 | "함께 만들어가는", "오너십" | "조직 내 성장 경로" |
| 주의사항 | 과도한 "빠른 성장" 강조로 번아웃 암시 주의 | 관료적 언어로 우수 인재 기피 주의 |

### 개발자 JD vs 마케터 JD

| 항목 | 개발자 | 마케터 |
|------|--------|--------|
| 자격 요건 핵심 | 기술 스택 명확히 (언어, 프레임워크, 버전) | 채널 전문성 (GA4, Meta Ads 등 + 성과 지표) |
| 수치 강조 | MAU, TPS, 레이턴시 등 | ROAS, CAC, CTR, 전환율 등 |
| 문화 언어 | 코드리뷰, 테스트, 기술 부채 | A/B 테스트, 데이터 드리븐, 퍼널 |
| 우대 사항 | 오픈소스 기여, 사이드 프로젝트 | 콘텐츠 포트폴리오, 업계 매체 기고 |
| 주의사항 | 너무 긴 기술 스택 목록 → 지원 기피 | 모호한 "콘텐츠 크리에이터" 표현 |

## 2.4 Copilot으로 JD 만들기 — 단계별 실습

### 단계 1. 기본 JD 초안 생성

Copilot Chat에 아래 프롬프트를 입력하세요.

```
시니어 백엔드 개발자 (Java/Spring) JD 초안 작성.

회사 유형: B2B SaaS 스타트업 (Series A, 직원 50명)
팀: 서버개발팀 (개발자 6명, TL 1명)
보고: CTO 직속

주요 업무:
- REST API 설계·개발·운영
- MySQL 스키마 설계 및 쿼리 최적화
- 코드리뷰 참여 및 기술 문서 작성
- 신규 기능 기획 단계 기술 검토

기술 스택: Java 17, Spring Boot 3, JPA/Hibernate, MySQL, AWS (ECS/RDS)

구조:
1. 포지션 소개 (4문장, 왜 이 역할인지)
2. 주요 업무 (불릿 7개)
3. 자격 요건 (불릿 5개, Must-have만)
4. 우대 사항 (불릿 3개)
5. 우리 팀 소개 (3문장)
6. 성장 기회 (2문장)

편향 없는 표현. Markdown 출력.
```

### 단계 2. 편향 검토 실행

단계 1 결과를 그대로 이어서 Chat에 다음을 입력하세요.

```
위 JD를 편향 언어 관점에서 검토해줘.

검토 항목:
1. 성별 편향 (특정 성별을 연상시키는 표현)
2. 연령 편향 (나이를 암시하는 표현)
3. 학력/출신 편향 (학벌, 출신 지역 등)
4. 신체 조건 편향 (외모, 체력 등)
5. 채용절차법 위반 소지 (혼인, 가족, 재산 등)

결과 형식:
- 발견된 표현 → 편향 유형 → 개선안
- 문제 없으면 "해당 없음"
- 편향 제거된 최종 수정본 전체 출력
```

### 단계 3. 스타트업 톤으로 조정

편향 검토가 끝난 JD를 스타트업답게 조정합니다.

```
위 JD를 스타트업 톤으로 다듬어줘.

- 딱딱한 문어체 표현을 친근하지만 전문적인 표현으로
- 포지션 소개에 "우리가 왜 이 사람을 필요로 하는지" 에너지 담기
- 스톡옵션, 자율 재택, 코드리뷰 문화 한 줄씩 추가
- 길이: 전체 500자 이내로 유지
- 여전히 편향 없는 표현 유지
```

### 단계 4. SNS용 요약 생성

```
위 JD를 LinkedIn 채용 공고용으로 요약.

- 길이: 200자 이내
- 포함: 역할명, 핵심 기술(2개), 팀 특징, 지원 방법
- 이모지 2개 이하
- CTA: "채용 페이지에서 지원하세요" (링크 자리표시자 포함)
```

## 2.5 실전 예시 — 완성된 JD 비교

### 편향 있는 JD (Before)

```
시니어 백엔드 개발자 채용

저희 회사는 젊고 패기 있는 개발자를 찾고 있습니다.

자격 요건:
- 4년제 컴퓨터공학 관련 학과 졸업
- Java 개발 경력 7년 이상의 베테랑
- 체력이 강하고 야근에 유연한 분
- 단정하고 협조적인 성격

우대 사항:
- 명문대 출신 우대
- 군필 또는 면제자
```

### 편향 없는 JD (After)

```markdown
## 시니어 백엔드 개발자 — Java/Spring

저희 서버개발팀은 B2B SaaS 플랫폼의 핵심 API를 만듭니다.
팀이 빠르게 성장하면서, API 설계와 성능 최적화를 주도할 수 있는
경험 있는 백엔드 개발자가 필요해졌습니다.

### 주요 업무
- REST API 설계·개발·운영 (Spring Boot 3 기반)
- MySQL 스키마 설계 및 쿼리 최적화
- 코드리뷰 참여 및 기술 문서 작성
- 신규 기능 기획 단계 기술 타당성 검토
- 팀 내 기술 표준 정립 및 공유

### 자격 요건
- Java 백엔드 개발 실무 경험 3년 이상
- Spring Boot를 활용한 REST API 개발 경험
- RDB 설계 및 쿼리 최적화 경험 (MySQL 또는 PostgreSQL)
- 버전 관리 도구(Git) 활용 능숙

### 우대 사항
- AWS ECS/RDS 운영 경험
- 테스트 코드 작성 습관 (JUnit 등)
- 기술 블로그 또는 오픈소스 기여 경험

### 우리 팀 소개
개발팀 6명이 주 2회 코드리뷰 세션을 운영하고, 기술 부채를 꾸준히 관리하는
문화를 갖고 있습니다. 자율 재택 (주 3일)을 지원하며, 스톡옵션도 제공합니다.

### 성장 기회
업무 범위를 본인이 주도적으로 넓힐 수 있으며, 기술 리드로 성장할 수 있는
로드맵을 함께 설계합니다. 컨퍼런스 참가비와 도서 구매는 전액 지원합니다.
```

**핵심 차이**
- "젊고 패기 있는" → 삭제
- "7년 이상의 베테랑" → "3년 이상" (역량 중심으로)
- "체력이 강하고 야근에 유연한" → 삭제 (야근 강요 인상 제거)
- "명문대 출신 우대" → 삭제
- "군필 또는 면제자" → 삭제

이 실습은 이 챕터의 핵심입니다. 단계별로 직접 실행하세요.


## 핵심 포인트

1. JD의 6섹션 구조: 소개 / 업무 / 자격(Must) / 우대(Nice) / 팀 / 성장
2. 자격 요건은 짧게 — Must-have만. 나머지는 우대 사항으로 이동
3. **편향 검토는 JD 생성과 별도로 반드시 실행** — Copilot 초안도 예외 없음
4. 스타트업 JD: 짧고 에너지 있게. 대기업 JD: 상세하고 격식 있게
5. 개발자 JD: 기술 스택 명확히. 마케터 JD: 채널·KPI 구체적으로
6. 채용절차법 위반 표현(학력·외모·혼인 등)은 Copilot 생성본에도 포함될 수 있음
