# 03. 인터뷰 질문 설계 — BEI, STAR, 루브릭까지

## 학습 목표

- 행동면접(BEI)과 STAR 구조를 이해하고 질문 세트를 즉시 생성
- 컬처핏(Culture Fit) vs 컬처애드(Culture Add)의 차이와 편향 위험
- 역할별 인터뷰 질문 20개 + 평가 루브릭을 Copilot으로 완성
- 법적으로 물으면 안 되는 질문을 면접관 교육 자료로 만들기

**예상 소요**: 60분 (실습 포함)

---

## 3.1 인터뷰 질문 설계의 세 가지 원칙

좋은 인터뷰 질문은 세 가지를 동시에 만족합니다.

1. **예측 타당성**: 이 질문의 답이 실제 직무 성과를 예측하는가
2. **공정성**: 모든 지원자에게 동일한 기준으로 적용되는가
3. **법적 안전성**: 금지된 개인정보를 묻지 않는가

구조화 면접(Structured Interview)은 이 세 가지를 가장 잘 충족합니다. 모든 지원자에게 동일한 질문을 동일한 순서로 묻고, 사전에 정의된 루브릭으로 평가합니다. 비구조화 면접보다 채용 후 성과 예측력이 2배 높다는 연구 결과도 있습니다.

## 3.2 행동면접(BEI)과 STAR 구조

### BEI(Behavioral Event Interview)란

"과거 행동이 미래 행동을 예측한다"는 전제에 기반합니다. 지원자가 실제로 겪은 상황을 서술하게 해서 역량을 평가합니다.

**BEI가 아닌 질문 (가정/의견)**
```
"팀 내 갈등이 생기면 어떻게 하시겠어요?"
→ 이상적인 답을 말할 수 있음. 실제 행동과 무관.
```

**BEI 질문 (실제 경험 유도)**
```
"팀원과 의견 충돌이 있었던 상황을 말씀해 주세요.
어떤 상황이었고, 어떻게 해결하셨나요?"
→ 실제 행동 기반. 평가 가능.
```

### STAR 구조

BEI 답변을 구조화하는 프레임워크입니다. 질문 설계와 평가 모두에 활용합니다.

| 요소 | 의미 | 평가자가 확인할 것 |
|------|------|------------------|
| **S**ituation | 어떤 상황이었나 | 맥락의 복잡성, 이해도 |
| **T**ask | 무엇을 해야 했나 | 책임의 범위와 명확성 |
| **A**ction | 본인이 구체적으로 한 일 | 주도성, 의사결정 과정 |
| **R**esult | 결과가 어떻게 됐나 | 수치 기반 성과, 학습 |

**면접관 팁**: "구체적으로 말씀해 주세요", "본인의 역할이 무엇이었나요?" 같은 후속 질문(Probe)으로 STAR 각 요소를 끌어냅니다.

## 3.3 컬처핏 vs 컬처애드

### 컬처핏의 문제

"우리 팀과 잘 맞는 사람"을 찾는 것처럼 보이지만, 실제로는 **기존 팀과 비슷한 사람**을 선호하는 결과로 이어집니다. 이것이 동질성(homogeneity) 편향입니다.

컬처핏 면접은 의도치 않게 다음을 걸러냅니다.
- 다른 업계 출신 (경험의 다양성 제거)
- 다른 의사소통 스타일 (내향적 지원자)
- 다른 문화적 배경 (DEI 저해)

### 컬처애드(Culture Add)란

기존 팀에 없는 새로운 관점·경험·역량을 더할 수 있는 사람을 찾는 접근법입니다.

**컬처핏 질문 (위험)**
```
"우리 팀은 다들 야근도 마다하지 않고 열정적이에요.
그런 환경에 잘 적응하실 것 같으신가요?"
→ 기존 문화의 동질화. 야근을 당연시하는 문화 강화.
```

**컬처애드 질문 (권장)**
```
"기존 팀 방식에 의문을 제기하고 더 나은 방식을 제안했던 경험을 말씀해 주세요."
→ 변화를 이끄는 역량 탐색. 다양한 배경 가진 지원자에게도 공정.
```

### 컬처애드 관점 질문 예시

1. "이전 팀에서 본인만의 강점으로 팀에 기여했던 방식이 있다면?"
2. "팀 내 다양한 시각이 도움이 됐던 경험을 말씀해 주세요."
3. "본인이 팀에 없는 어떤 관점을 가져올 수 있다고 생각하시나요?"

## 3.4 인터뷰 질문의 금지 영역

면접에서 아래를 묻거나 암시하는 질문은 법적·윤리적으로 금지입니다.

### 법적 금지 (채용절차법·근로기준법)

| 금지 질문 | 대체 (역량 중심) |
|-----------|----------------|
| "결혼하셨어요?" / "결혼 계획이 있으신가요?" | "장기 프로젝트 참여에 어려움이 있으신가요?" |
| "자녀가 있으신가요?" / "자녀 계획은?" | 질문하지 않음 (업무 수행에 무관) |
| "나이가 어떻게 되세요?" | 질문하지 않음 (서류에 생년월일 없으면 더 좋음) |
| "종교가 있으신가요?" | 질문하지 않음 |
| "부모님은 뭐 하세요?" | 질문하지 않음 |
| "몸무게/키가 어떻게 되세요?" | 신체 조건이 직무에 필수인 경우만 서면으로 |
| "재산이나 부채가 있으신가요?" | 금융기관 특수직 외 금지 |
| "정치적으로 어떤 성향이세요?" | 질문하지 않음 |

### 주의해야 할 그레이 존

직접 묻지 않아도 유추 가능한 질문들도 주의가 필요합니다.

- "저희 팀이 야근이 많은데 괜찮으세요?" → 가족 상황을 묻는 우회 표현
- "해외 출장이 잦은데 문제 없으신가요?" → 직무 필수 요건이라면 OK, 가정 상황 타진 의도라면 NG
- "거주지가 어디세요?" → 통근 가능 여부는 물을 수 있으나 지역 편견 의도라면 NG

## 3.5 Copilot으로 인터뷰 질문 세트 만들기

### 프롬프트 1. 기본 BEI 질문 세트

```
시니어 PM(Product Manager) BEI 인터뷰 질문 세트 20개 작성.

평가 역량 4개, 각 역량당 5개:
1. 프로덕트 전략 및 우선순위화
2. 데이터 기반 의사결정
3. 이해관계자 관리 및 커뮤니케이션
4. 실행력 및 문제 해결

각 질문:
- STAR 답변을 유도하는 BEI 형식
- 후속 질문(Probe) 1개씩 포함
- 금지 질문(나이/혼인/자녀/종교/출신 지역) 없음

출력: 역량별 섹션, Markdown.
```

### 프롬프트 2. 평가 루브릭 생성

질문 세트를 만든 뒤 바로 이어서:

```
위 인터뷰 질문에 대한 평가 루브릭 작성.

역량 4개에 대해 각각:
- 1점 (기대 이하): 어떤 답변인지 서술
- 3점 (기대 충족): 어떤 답변인지 서술
- 5점 (기대 초과): 어떤 답변인지 서술

평가자가 같은 기준으로 점수를 매길 수 있도록 구체적으로.
출력: Markdown 표.
```

### 프롬프트 3. 역할별 기술 질문 (비기술 HR용)

```
HR 담당자가 프론트엔드 개발자 면접에서 활용할
비기술 관점 관찰 체크리스트 작성.

HR이 관찰할 수 있는 항목:
1. 기술 설명의 명확성 (비전문가에게 쉽게 설명하는 능력)
2. 문제 해결 사고 과정 공유 (접근 방법의 체계성)
3. 실수나 실패를 다루는 태도 (겸손함, 학습 지향)
4. 협업 방식 서술 (팀 기여도 vs 개인 공로 강조 균형)
5. 호기심·성장 욕구 신호

각 항목: 관찰 포인트 2~3개 + 긍정/부정 신호 예시
출력: Markdown 체크리스트.
```

### 프롬프트 4. 컬처애드 질문 세트

```
다양성·포용성 관점의 컬처애드(Culture Add) 인터뷰 질문 10개 작성.

목적:
- 기존 팀에 없는 새로운 관점·경험·강점 탐색
- 다양한 배경 지원자에게 공정한 기회

조건:
- 특정 배경(학력/출신/성별)이 유리하지 않은 질문
- 역량과 경험 중심
- 컬처핏(기존과 같은 사람) 선호 편향 없음

출력: 질문 + 의도(1~2줄) + 좋은 답변 방향 힌트
Markdown.
```

### 프롬프트 5. 면접관 교육용 금지 질문 가이드

```
면접관 대상 인터뷰 금지 질문 교육 가이드 작성.

대상: 처음 면접관으로 참여하는 팀장급
목적: 채용절차법·근로기준법 위반 예방

포함:
1. 왜 금지 질문이 문제인지 (법적 + 편향 관점 2가지)
2. 금지 질문 카테고리 6개와 실제 예시
3. 자주 하는 실수 상황 3개 (역할극 시나리오 포함)
4. 의도 좋아도 안 되는 질문들 ("가족이 응원해 주시나요?" 등)
5. 대체 질문 방법

분량: A4 1페이지 수준. 실용적이고 쉽게.
출력: Markdown.
```

## 3.6 직군별 인터뷰 질문 예시

### 시니어 PM — 주요 질문 5개

**역량: 프로덕트 우선순위화**
> "여러 이해관계자가 서로 다른 기능 요청을 동시에 넣어온 상황에서, 어떻게 우선순위를 정하셨나요? 그 과정에서 반대에 부딪혔다면 어떻게 설득하셨나요?"

**역량: 데이터 기반 의사결정**
> "데이터가 직관과 다른 방향을 가리켰던 적이 있나요? 어떻게 결정하셨나요?"

**역량: 실패 대응**
> "출시한 기능이 예상과 달리 사용자 반응이 없었던 경험이 있다면? 그때 어떻게 대응하셨나요?"

**역량: 이해관계자 관리**
> "C레벨 또는 핵심 이해관계자가 PM의 판단과 다른 방향을 원했을 때, 어떻게 상황을 풀어가셨나요?"

**역량: 성장 지향**
> "본인 PM 커리어에서 가장 크게 실패했던 결정은 무엇이고, 그것이 이후 어떤 변화를 만들었나요?"

### 백엔드 개발자 — 행동 면접 질문 3개 (HR용)

> "기술 부채가 심각했던 코드베이스를 다룬 경험이 있나요? 어떤 접근으로 해결하려 했나요?"

> "팀원과 코드 방향에 대해 의견이 달랐던 경험을 말씀해 주세요. 결론은 어떻게 났나요?"

> "촉박한 마감과 코드 품질 사이에서 트레이드오프를 결정해야 했던 상황이 있나요?"

### HRBP — 자기 직군 인터뷰 질문 3개

> "조직 진단 결과와 경영진이 원하는 방향이 달랐던 경험이 있나요? 어떻게 조율하셨나요?"

> "채용 속도를 압박받으면서도 채용 품질을 지켜야 했던 상황을 말씀해 주세요."

> "직원 한 명이 심각한 번아웃 신호를 보냈는데, 조직 구조상 바로 해결이 어려웠던 경험이 있나요? 어떻게 대응하셨나요?"

## 3.7 완성된 평가 루브릭 예시

### 역량: 데이터 기반 의사결정

| 점수 | 기준 | 예시 답변 특징 |
|------|------|---------------|
| **1점** | 데이터를 언급하지 않거나, 직감으로만 결정 | "그냥 느낌상 이게 맞을 것 같아서 했어요" |
| **2점** | 데이터를 봤으나 해석이 피상적 | "GA에서 이탈률이 높다고 나와서 수정했어요" |
| **3점** | 구체적 지표를 바탕으로 가설 수립 후 결정 | "CTR이 2%대였는데 업계 평균 3.5%와 비교해서 A/B 테스트 설계했고, 결과적으로 CTR 40% 개선했어요" |
| **4점** | 데이터와 맥락을 함께 해석, 한계 인식 | 위 + "데이터만 봤다면 놓쳤을 정성적 신호도 고려했어요" |
| **5점** | 불완전한 데이터 상황에서도 체계적 의사결정, 결과 측정까지 | 위 + "데이터가 없었던 상황에서 프록시 지표를 설계했고, 이후 실제 데이터와 비교해 보정했어요" |

## 실습 — 시니어 PM 인터뷰 세트 완성하기

이 실습의 목표는 **실제로 면접에 쓸 수 있는** 인터뷰 패키지를 만드는 것입니다.

**Step 1**: Copilot Chat에서 아래 프롬프트를 실행하세요.

```
시니어 PM 구조화 인터뷰 세트 완성본 작성.

역량 4개:
1. 프로덕트 전략 및 우선순위화
2. 데이터 기반 의사결정
3. 이해관계자 커뮤니케이션
4. 실행력과 문제 해결

각 역량당:
- BEI 질문 4개 (STAR 유도형)
- 후속 질문(Probe) 각 1개
- 평가 루브릭 (1/3/5점 기준)

추가:
- 오프닝 인사말 (5분, 라포 형성용)
- 지원자가 질문할 시간 안내 멘트

금지: 나이·혼인·자녀·종교 관련 질문 없음
출력: 전체 인터뷰 가이드 형식, Markdown
```

**Step 2**: 결과를 `interview-guide-senior-pm.md`로 저장합니다.

**Step 3**: 본인이 한 가지 역량의 루브릭이 너무 모호하다고 느끼면, 다음 프롬프트로 구체화하세요.

```
위 루브릭에서 [역량명]의 3점 기준이 너무 모호해.
실제 PM 답변 예시를 2~3줄로 구체화해줘.
```

**Step 4 (보너스)**: 금지 질문 카드를 만들어보세요.

```
인터뷰 면접관이 참고할 "금지 질문 카드" 작성.
- 카드 크기: A6 (절반 접이식)
- 앞면: 자주 하는 금지 질문 10개 (빨간 X 표시)
```
