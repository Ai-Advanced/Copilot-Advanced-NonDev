# 08. 캡스톤 — "시니어 개발자 채용 A~Z"

## 캡스톤 목표

2일 과정에서 배운 모든 것을 하나의 현실적인 시나리오에 적용합니다. 이 캡스톤이 끝나면 실제 채용 현장에서 바로 꺼내 쓸 수 있는 패키지가 완성됩니다.

**예상 소요**: 60분

---

## 시나리오

> **회사**: 주식회사 그린테크 (GreenTech)
> B2B 탄소 배출 관리 SaaS 스타트업, Series B, 직원 150명
> 서울 강남구, 하이브리드 근무 (주 3일 오피스)
>
> **상황**: 공동 창업자 겸 CTO 김태호 씨가 HRBP 이하나 씨에게 요청했습니다.
>
> "이번에 서버 사이드 아키텍처를 본격적으로 개선해야 해요. Spring Boot + MSA 전환 경험이 있는 시니어 백엔드 개발자가 한 명 필요합니다. 빠르면 6주 안에 입사했으면 좋겠어요. 이 포지션이 얼마나 중요한지는 알고 계시죠?"
>
> **여러분의 역할**: HRBP 이하나 씨. 지금부터 그 개발자가 입사 후 90일 리뷰를 받는 날까지의 모든 과정을 준비하세요.

---

## 단계 구성

```
Phase 1: 채용 준비 (JD + 편향검토 + 공고)
Phase 2: 전형 운영 (스크리닝 + 인터뷰 + 루브릭)
Phase 3: 오퍼 및 입사 (오퍼 레터 + 웰컴 이메일)
Phase 4: 온보딩 (체크리스트 + 90일 플랜)
Phase 5: 3개월 리뷰 (성과 리뷰 + 서베이)
```

---

## Phase 1. 채용 준비

### Step 1-A. 역할 정의

채용 킥오프 전 역할을 명확히 정의합니다.

**프롬프트**:
```
채용 킥오프 역할 정의 문서 작성.

역할명: 시니어 백엔드 개발자 (Spring Boot / MSA)
회사: GreenTech — B2B 탄소 배출 관리 SaaS (Series B, 150명)
배경: 모놀리식 → MSA 전환 프로젝트 진행 중
팀: 서버개발팀 (9명), TL 1명 포함

포함:
1. 이 역할이 필요한 비즈니스 이유 (3~4문장)
2. 입사 90일 후 성공 기준 3개 (측정 가능하게)
3. 핵심 기술 스택 (Java 17, Spring Boot 3, JPA, Kafka, AWS ECS)
4. 협업 팀과 방식 (프로덕트/인프라/QA)
5. 이 역할이 다루는 주요 도전 과제

출력: Markdown.
```

### Step 1-B. JD 작성 (편향 검토 포함)

**프롬프트**:
```
시니어 백엔드 개발자 JD 초안 작성.

회사: GreenTech — B2B 탄소 배출 관리 SaaS (Series B)
팀: 서버개발팀 9명
배경: MSA 전환 프로젝트의 핵심 포지션

핵심 업무:
- 모놀리식 → MSA 아키텍처 전환 기여
- 도메인 서비스 설계 및 API 개발 (Spring Boot 3)
- Kafka 기반 비동기 이벤트 시스템 설계
- 코드리뷰, 기술 문서화, 주니어 개발자 멘토링

기술 스택: Java 17, Spring Boot 3, JPA, Kafka, MySQL, AWS ECS/RDS

구조: 포지션 소개(4문장) / 주요 업무(7개) / 자격 요건(5개) / 우대 사항(3개) / 팀 소개(3문장) / 성장 기회(2문장)

편향 없는 표현. Markdown 출력.
```

JD 생성 후 바로 편향 검토:

```
위 JD를 편향 언어 관점에서 검토.

항목: 성별/연령/학력/신체 편향, 채용절차법 위반 소지
결과: 발견된 표현 → 유형 → 개선안 목록
편향 제거된 최종 JD 전체 출력.
```

결과물: `jd-senior-backend-greentech.md`

### Step 1-C. LinkedIn 공고 + 거절 이메일

**프롬프트**:
```
다음 두 가지를 작성:

1. LinkedIn 채용 공고 (200자 이내)
   - 역할명, 핵심 기술 2개, 팀 특징, 지원 CTA
   - 이모지 2개 이하

2. 서류 탈락 안내 이메일 (150자 이내)
   - 정중하고 진심 어린 톤
   - 구체적 탈락 사유 없음
   - 향후 재지원 가능성 열어두기
```

## Phase 2. 전형 운영

### Step 2-A. 이력서 스크리닝 매트릭스

**프롬프트**:
```
시니어 백엔드 개발자 이력서 스크리닝 매트릭스 작성.

Pass/Fail 기준 (하나라도 Fail이면 탈락):
1. Java 백엔드 개발 5년 이상
2. Spring Boot를 사용한 프로덕션 서비스 운영 경험
3. 마이크로서비스 아키텍처 설계 또는 참여 경험

점수 항목 (각 1~5점):
1. MSA/이벤트 드리븐 아키텍처 깊이
2. 성과 수치 구체성 (이력서에 정량 성과 포함)
3. AWS 운영 경험 (ECS/Lambda/RDS)
4. Kafka 또는 메시지 큐 경험
5. 멘토링 또는 기술 리더십 경험

기준: 20점 이상 → 1차, 13~19점 → 보류, 12점 이하 → 거절
주의: 학력·나이·성별 평가 항목 없음.
출력: Markdown 표.
```

### Step 2-B. 인터뷰 질문 세트 + 루브릭

**프롬프트**:
```
시니어 백엔드 개발자 구조화 인터뷰 세트 작성 (HR 행동 면접 파트).

평가 역량 4개:
1. 기술 리더십과 팀 기여
2. 복잡한 기술 문제 해결
3. 이해관계자 커뮤니케이션 (비기술 직군 포함)
4. 성장 지향과 자기 개발

각 역량당:
- BEI 질문 4개 (STAR 유도형)
- 후속 질문(Probe) 1개

평가 루브릭:
- 각 역량 1점/3점/5점 기준 (실제 답변 예시 포함)
- MSA 전환 경험 지원자에게 추가로 확인할 사항

금지: 나이·혼인·자녀·종교·외모 관련 질문 없음
출력: 전체 인터뷰 가이드, Markdown.
```

### Step 3-A. 오퍼 레터 초안

**프롬프트**:
```
채용 오퍼 레터 초안 작성.

회사: GreenTech
역할: 시니어 백엔드 개발자
입사 예정일: [DATE] (자리표시자)

포함:
- 환영 인사 (진심 어린, 2~3문장)
- 포지션명, 팀, 보고 라인
- 보상 패키지 (금액 대신 [BASE_SALARY], [BONUS], [STOCK_OPTIONS] 자리표시자)
- 복리후생 하이라이트 5개 (재택 정책, 장비 지원, 컨퍼런스 지원, 점심, 스톡옵션)
- 오퍼 수락 기한 (발송 후 5 영업일)
- 근로계약서 별도 체결 안내
- 담당 HR 연락처

톤: 환영과 기대감이 느껴지게. 법적 의무 고지 포함.
출력: Markdown.
```

**프롬프트**:

톤: 따뜻하고 실용적. 개발자 문화 반영 (GitHub, PR 등 용어 자연스럽게).

```
시니어 백엔드 개발자 신규 입사자 온보딩 체크리스트 작성.

특이사항:
- MSA 전환 프로젝트 진행 중 → 아키텍처 파악이 중요
- 코드리뷰 문화 강함 → PR 프로세스 숙지 필요
- 개발 도구: IntelliJ, GitHub, Jira, Slack, Confluence

기간: 1주차 / 2주차 / 3~4주차 / 2개월차 / 3개월차

항목 유형:
- 계정·환경 세팅 (GitHub, AWS, Jira, Confluence, VPN)
- 아키텍처 이해 (현재 시스템 구조, MSA 전환 문서 리딩)

컬럼: 항목 | 담당자 | 완료 기한 | 완료
출력: Markdown 표.
```

### Step 4-B. 90일 온보딩 플랜

**프롬프트**:
```

컨텍스트:
- MSA 전환 프로젝트 진행 중
- 팀에서 즉시 의미 있는 기여를 기대
- 멘토링 역할도 기대 (주니어 2명 있음)

단계:
1~30일 (학습):
- 목표: 시스템 아키텍처 파악 + 팀 프로세스 적응
- 첫 PR (작은 개선) 완료

31~60일 (기여):
- 목표: MSA 전환 중인 도메인 서비스 1개 참여
- 코드리뷰 능동적으로 참여 시작

61~90일 (성과):
- 목표: 독립적으로 서비스 1개 설계·개발 주도
- 주니어 개발자 코드리뷰 멘토링 시작

각 단계: 핵심 목표 3개 + 액션 아이템 + 체크포인트 질문 3개
출력: Markdown.
```

1. AI는 초안 생성기, **최종 판단은 사람이**
