# HR 프롬프트 치트시트

> **사용법**: VS Code Copilot Chat 사이드바(`Ctrl+Alt+I`)에 그대로 복사-붙여넣기.
> `[대괄호]` 안의 내용을 실제 정보로 교체한 뒤 실행하세요.
> 실제 직원/지원자 개인정보(이름, 연락처, 주민번호)는 절대 입력하지 마세요.

---

## 1. 채용 — JD(Job Description) 작성

### P-01. 역할별 JD 초안 생성

```
[역할명] JD 초안 작성. 회사 유형: [스타트업/중견기업/대기업].

구조:
1. 포지션 소개 (3~4문장, 왜 이 역할이 중요한가)
2. 주요 업무 (불릿 6~8개)
3. 자격 요건 (불릿 5~6개, Must-have만)
4. 우대 사항 (불릿 3~4개, Nice-to-have)
5. 우리 팀 소개 (2~3문장)
6. 성장 기회 (2~3문장)

톤: 명확하고 구체적, 성별·연령·학력 차별 표현 없이.
출력: Markdown.
```

### P-02. 스타트업 스타일 JD

```
다음 역할의 스타트업 스타일 JD 작성: [역할명]

스타트업 특성:
- 팀 규모: [예: 개발자 8명, 전체 30명]
- 시리즈: [예: Series A]
- 도메인: [예: B2B SaaS, 핀테크]

스타트업 JD답게:
- 자율성과 오너십을 강조
- "빠르게 성장하는 환경" 어필
- 스톡옵션/복지 간략히 포함
- 딱딱한 관료 언어 배제, 구어체 허용
- 길이: 400자~500자 (짧고 임팩트 있게)

출력: Markdown.
```

### P-03. 대기업 스타일 JD

```
다음 역할의 대기업 스타일 JD 작성: [역할명], [부서명], [계열사/사업부]

특성:
- 직급 체계: [예: 책임/수석 or 과장/차장]
- 주요 프로세스 강조 (협업 절차, 승인 체계 등)
- 복리후생 포함 (4대보험, 연차, 교육비 등)
- 공채/수시 명시
- 톤: 정중하고 격식 있는 문어체

출력: Markdown.
```

### P-04. JD 편향(bias) 검토

```
아래 JD 텍스트를 편향 언어 관점에서 검토해줘.

검토 항목:
1. 성별 편향 (예: "젊고 활발한", "부드러운 소통" 등 특정 성별 연상 표현)
2. 연령 편향 (예: "패기 있는 신입", "경력 10년 이상의 베테랑")
3. 학력/출신 편향 (예: "명문대 졸업", "SKY 우대")
4. 외모/신체 편향 (예: "단정한 외모", "체력이 강한")
5. 국적/언어 편향 (예: "한국인 우대", 불필요한 영어 유창성 요구)
6. 근로기준법·채용절차법 위반 소지 (나이, 혼인 여부, 가족 관계 등 질문 금지 항목 포함 여부)

결과 형식:
- 발견된 편향 표현 목록 (원문 → 편향 유형 → 개선안)
- 문제 없으면 "편향 없음" 명시
- 최종 수정본 전체 출력

[--- JD 시작 ---]
(JD 텍스트 붙여넣기)
[--- JD 끝 ---]
```

## 3. 채용 — 인터뷰 설계

### P-12. BEI 인터뷰 질문 세트 생성

```
[역할명] 행동면접(BEI) 질문 세트 20개 작성.

역할 핵심 역량:
1. [역량1 예: 문제 해결력]
2. [역량2 예: 협업/커뮤니케이션]
3. [역량3 예: 주도성/오너십]
4. [역량4 예: 성과 지향성]

각 역량당 5개 질문:
- STAR 형식 유도 질문 (Situation-Task-Action-Result)
- 후속 질문(Follow-up) 1개씩 포함
- 금지: 나이/결혼/자녀/종교/출신 지역 관련 질문

출력: 역량별 섹션, Markdown.
```

### P-13. 컬처핏 vs 컬처애드 질문

```
우리 팀 문화 가치에 맞는 인터뷰 질문 10개 작성.

팀 가치관:
- [예: 투명한 소통, 빠른 실행, 서로 가르치는 문화, 다양성 존중]

컬처애드(Culture Add) 관점으로:
- 기존 팀에 없는 다양성을 더할 수 있는 관점 탐색
- "우리와 같은 사람"을 찾는 컬처핏이 아니라, "우리를 더 좋게 만들 사람"을 탐색
- 다양한 배경·경험 가진 지원자에게도 공정한 질문

출력: 질문 + 각 질문의 의도(1~2줄) 포함.
```

### P-14. 기술 면접 질문 (비기술 담당자용 가이드)

```
HR 담당자가 [역할명] 기술 면접을 함께 진행할 때 참고할 체크리스트 작성.

포함:
1. 확인해야 할 기술 역량 목록 (개발팀 제공 기준)
2. 비기술 HR이 관찰·평가할 수 있는 포인트 (설명 명확성, 사고 과정, 문서화 습관 등)
3. 기술 과제 결과물 검토 시 HR이 볼 수 있는 비기술 평가 항목

형식: 체크리스트 Markdown.
```

### P-16. 오퍼 레터 초안

```
채용 오퍼 레터 초안 작성.

포함 항목:
- 환영 인사 (진심 어린, 형식적이지 않게)
- 포지션명, 입사일
- 연봉, 인센티브 구조 (금액 대신 [AMOUNT] 자리표시자 사용)

톤: 따뜻하고 회사의 기대감이 느껴지게. 법적 의무 고지 포함 (근로계약서 별도 체결 안내).
출력: Markdown.
```

## 4. 온보딩

### P-17. 역할별 온보딩 체크리스트

```
[역할명] 신규 입사자 온보딩 체크리스트 작성.

기간: 1주차 / 2주차 / 3주차 / 4주차 / 2개월차 / 3개월차

각 기간별 체크 항목:
- 회사/시스템 이해 (IT 계정, 툴 세팅)

- 관계 구축 (1:1 일정, 점심 미팅)
- 성과 기준 이해 (KPI 합의, 90일 목표 설정)

컬럼: 항목 | 담당자 | 완료 기한 | 확인 여부
출력: Markdown 표.
```

### P-18. 웰컴 이메일 작성

```
신규 입사자에게 보내는 웰컴 이메일 작성.

발신: HR팀 또는 HRBP
수신: 신규 입사자 [이름 자리표시자]
입사일: [DATE]
역할: [역할명]

포함:
- 진심 어린 환영 메시지 (2~3문장)
- 첫날 준비사항 (복장, 도착 시간, 주차, 점심)
- 받게 될 메일/링크 안내 (IT 계정, 노션, 슬랙 등)
- 담당 HR 연락처
- 입사 전 읽을 자료 1~2개 (선택)

톤: 따뜻하고 구체적. 불안감 해소에 집중.
```

### P-19. 90일 온보딩 플랜 (역할별)

```
[역할명] 신규 입사자 90일 온보딩 플랜 작성.

- 구체적 액션 아이템 (담당자 포함)
```


### P-23. 360도 피드백 문항 설계

```
[역할명] 대상 360도 피드백 설문 문항 작성.

응답자 유형별:
- 관리자 (5문항)
- 동료 (5문항)
- 부하/협업자 (5문항)
- 셀프 (5문항)

문항 유형:
```
