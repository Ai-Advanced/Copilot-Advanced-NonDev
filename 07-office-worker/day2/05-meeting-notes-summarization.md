# 05. 회의록 자동 정리 — 30분 회의를 5분 요약으로

## 학습 목표

- 러프한 회의 노트를 Copilot으로 정식 회의록으로 변환하는 흐름 습득
- 액션 아이템 자동 추출 + 담당자 태깅 + 마감일 표 정리
- 회의록을 이메일/슬랙/팀즈에 맞는 형식으로 변환하기
- 회의록 표준 템플릿을 재사용 가능한 형태로 만들어두기

**예상 소요**: 60분 (실습 포함)

---

## 5.1 회의록 정리가 왜 그렇게 오래 걸리나

회의가 끝나고 회의록을 정리할 때 실제로 시간이 걸리는 구간은 이렇습니다.

1. **손으로 적은 노트를 타이핑으로 옮기는 것** — 20분
2. **순서가 뒤섞인 안건을 주제별로 묶는 것** — 5~10분
3. **각 담당자별 해야 할 일을 따로 추려내는 것** — 5~10분
4. **공식 회의록 형식에 맞게 레이아웃을 잡는 것** — 5~10분
5. **공유 메시지를 따로 또 만드는 것** — 5분

합산하면 30분짜리 회의에 **35~55분** 의 후처리가 붙습니다.

Copilot을 쓰면 이 전체를 **10~15분**으로 줄일 수 있습니다. 단계 1~4가 자동화되기 때문입니다. 여러분이 하는 건 노트를 붙여넣고 사실 관계를 검토하는 것뿐입니다.

---

## 5.2 회의록 자동화 흐름 4단계

```
[단계 1] 회의 중 러프하게 적는다 (VS Code 또는 메모앱)
     ↓
[단계 2] 노트를 VS Code에 붙여넣고 정식 회의록 변환 요청
     ↓
[단계 3] 액션 아이템 추출 + 담당자/마감일 표 생성
     ↓
[단계 4] 목적에 맞는 공유 포맷으로 변환 (이메일/슬랙/팀즈)
```

이 4단계가 전체 흐름입니다. 각 단계를 하나씩 해봅니다.

---

## 5.3 단계 1 — 회의 중 어떻게 적을까

회의 중에 완벽한 문장으로 적으려 하지 마세요. 오히려 방해가 됩니다. 아래처럼 키워드와 단편 문장으로 빠르게 적는 것이 Copilot 활용에 더 좋습니다.

**잘 쓴 회의 노트 예시**:

```
7/20 14:00 - 8월 워크숍 준비 회의
참석: 박부장, 이팀장, 최대리, 홍길동

안건1. 장소
- 제주 연수원 (이팀장 확인) → 가능, 8/22~23 (금토)
- 숙박 30명분 필요
- 이팀장이 예약 진행 → 이번 주 금요일까지

안건2. 프로그램
- 팀빌딩 게임 원함 (박부장)
- 외부 강사 또는 내부 진행 중 고민
- 최대리가 외부 업체 3곳 견적 알아보기 → 다음 주 월요일까지
- 예산: 1인당 5만원 이내

안건3. 이동
- 렌트카 vs 버스 논의
- 버스 쪽이 낫겠다 (비용+편의성)
- 홍길동이 버스 업체 2~3곳 견적 요청 → 이번 주 금요일

기타
- 참가 확인서 7월 25일까지 취합 (담당: 홍길동)
- 다음 회의: 7월 27일 (월) 10시
```

이 정도면 충분합니다. 이제 Copilot으로 넘깁니다.

## 5.5 단계 3 — 액션 아이템만 별도 추출

회의록 전체가 아니라 담당자별로 "내가 뭘 해야 하나"를 빠르게 보고 싶을 때 씁니다.

**프롬프트**:

```
위 회의록에서 액션 아이템만 담당자별로 묶어서 표로 정리해줘.

표 열: 담당자 | 액션 내용 | 마감일 | 상태
상태 컬럼은 모두 "미완료"로 초기값 설정.
담당자 알파벳/가나다 순 정렬.
```

**결과**:

| 담당자 | 액션 내용 | 마감일 | 상태 |
|--------|-----------|--------|------|
| 이팀장 | 제주 연수원 예약 진행 | 7/25 | 미완료 |
| 최대리 | 팀빌딩 외부 업체 3곳 견적 확인 | 7/28 | 미완료 |
| 홍길동 | 버스 업체 2~3곳 견적 요청 | 7/25 | 미완료 |
| 홍길동 | 참가 확인서 취합 | 7/25 | 미완료 |

이 표를 각 담당자에게 공유하면 "내가 뭘 해야 하는지" 즉시 알 수 있습니다.

## 5.6 단계 4 — 공유 포맷 변환

### 슬랙/팀즈 공유 메시지

긴 회의록 전체를 올리는 대신, 핵심 요약만 채널에 공유합니다.

**프롬프트**:

```
위 회의록을 슬랙/팀즈 채널 공유용 짧은 메시지로 변환.

조건:
- 이모지 적절히 사용 (과하지 않게)
- 10줄 이내
- 주요 결정 사항 2~3개 불릿
- 각자 할 일 간략히 언급
- 다음 회의 일정 포함
- 마지막 줄: 전체 회의록 링크 안내 자리 (URL은 플레이스홀더로)
```

**결과 예시**:

```
📋 8월 워크숍 준비 회의 결과 공유드립니다!

✅ 주요 결정
• 장소: 제주 연수원, 8/22~23 (1박 2일) 확정
• 이동: 버스 이용 방향 (견적 후 최종 확정)
• 프로그램: 외부 업체 견적 확인 후 결정

📌 이번 주 할 일
• 이팀장 — 연수원 예약 (7/25)
• 최대리 — 팀빌딩 업체 견적 3곳 (7/28)
• 홍길동 — 버스 견적 + 참가 확인서 취합 (7/25)

🗓️ 다음 회의: 7/27(월) 오전 10시

📄 전체 회의록: [링크 첨부 예정]
```

### 이메일 공유 형식

외부 협력사나 임원에게 회의 결과를 이메일로 보낼 때는 다른 포맷이 필요합니다.

**프롬프트**:

```
위 회의록을 외부 협력사에 공유하는 공식 이메일 형식으로 변환.

수신: 제주 연수원 담당자 (이름 미상)
목적: 워크숍 장소 예약 요청 및 조건 확인
포함:
- 행사 개요 (날짜/인원/목적)
- 필요 사항 (숙박 30명, 식사 포함 여부 확인)
- 연락 요청 (견적서 + 예약 가능 여부)
톤: 정중하고 공식적으로
서명: 이팀장 이름 플레이스홀더 포함
```

## 5.7 회의록 템플릿 재사용

매번 프롬프트를 쓰는 대신, 표준 회의록 템플릿 파일을 만들어두면 더 빠릅니다.

VS Code에서 `templates/meeting-notes-template.md`를 열고 (또는 새로 만들고) Copilot에 요청:

```
회의록 표준 Markdown 템플릿 작성.

포함 섹션:
1. 회의 개요 (일시/장소/참석자/목적/주관자)
2. 안건 목록 (3개 자리, 추가 가능)
3. 각 안건별 (논의 내용 / 결정 사항 / 보류 항목)
4. 액션 아이템 표 (번호/내용/담당자/마감일/상태)
5. 미결 사항
6. 다음 회의 정보

형식: 채울 수 있는 플레이스홀더 [날짜], [이름] 등 표시
재사용하기 쉽게 섹션별로 구분선(---) 사용
```

이 템플릿을 저장해두면, 다음 회의 후에는 내용만 채우면 됩니다.

## 5.8 특수 상황 — 음성 녹취록 처리

회의 녹화 파일의 자동 전사(STT) 텍스트를 받았을 때는 노트보다 더 지저분합니다. 화자 표시가 없거나, 같은 말이 반복되거나, 비언어 표현이 섞여 있습니다.

**프롬프트 (녹취록 전용)**:

```
아래 회의 자동 녹취록을 정리해줘.

처리 방법:
1. "음", "그러니까", "뭐" 같은 불필요한 구어체 표현 제거
2. 같은 내용의 반복 발언은 한 번만 정리
3. 화자 구분이 있으면 유지, 없으면 주제 흐름으로 안건 구분
4. 결정 사항과 액션 아이템이 나오면 강조 표시
5. 최종 형식: 안건별 요약 + 결정사항 + 액션아이템 표

[--- 녹취록 ---]
(자동 전사 텍스트 붙여넣기)
[--- 끝 ---]
```

## 실습 — 30분 회의 노트 → 5분 요약 + 액션 리스트

### 실습용 회의 노트

아래 노트를 사용하거나, 실제 여러분 업무의 최근 회의 노트로 대체하세요.

```
7/21 11:00 경영지원 주간 회의
참석: 김부장, 이대리, 박사원, 나(홍길동)

1. 총무 현황
- 사무용품 신청 마감: 이번 주 수요일 오전까지
- 아직 미신청: 기획팀, QA팀
- 박사원이 오늘 중으로 독촉 이메일 보내기
- 에어컨 수리: 3층 2대 고장 → AS 접수 이미 했음, 이번 주 목요일 기사 방문 예정

2. 비용 처리
- 6월 법인카드 정산 마감 7/25
- 아직 미제출 2명 (이름 공유 별도)
- 이대리가 미제출자에게 개별 연락 → 7/22까지
- 영수증 없는 건: 김부장이 판단 후 반려 or 승인

3. 행사
- 창립기념일 행사 준비 (8/15)
- 케이터링 업체 선정: 홍길동이 3곳 비교 → 7/24
- 예산 50만원 이내
- 참석 인원 확인 필요: 이대리가 각 팀장에게 확인 → 7/22
- 행사 장소: 10층 대회의실 (이미 예약 완료)

기타 - 복사기 3호기 토너 교체 필요, 박사원 담당
다음 주 회의: 7/28 11:00
```

### 실습 단계

**Step 1.** 위 노트를 VS Code에 새 파일(`meeting-0721.md`)로 저장합니다.

**Step 2.** Chat에서 정식 회의록 변환 프롬프트를 입력합니다 (5.4절 참고).

**Step 3.** 결과를 검토하면서 사실 관계를 확인합니다.
- 마감일이 정확한가?
- 담당자가 맞는가?
- 빠진 안건이 없는가?

**Step 4.** 액션 아이템만 별도 추출 프롬프트를 씁니다 (5.5절 참고).

**Step 5.** 슬랙 공유 메시지를 생성합니다 (5.6절 참고).

**Step 6.** 총 걸린 시간을 측정합니다. 10분 이내를 목표로 합니다.

완성한 회의록을 아래 기준으로 확인합니다:

- [ ] 모든 안건이 포함되었나?
- [ ] 결정 사항이 미결 사항과 명확히 구분되는가?
- [ ] 액션 아이템에 담당자와 마감일이 모두 있는가?
- [ ] 없던 정보(마감일 등)를 Copilot이 임의로 만들지는 않았는가?
- [ ] 슬랙 메시지가 10줄 이내인가?

---

## 핵심 포인트

1. **회의 중에는 키워드만** — 완벽한 문장 불필요, 나중에 Copilot이 정리
2. **4단계 흐름**: 노트 → 정식 회의록 → 액션 아이템 표 → 공유 메시지
3. **사실 관계 검토는 필수** — 담당자·마감일·결정 내용을 반드시 확인
4. **표준 템플릿을 한 번 만들어두면** 매번 프롬프트 없이 내용만 채우면 됨
5. 녹취록도 Copilot으로 정리 가능 — 구어체 제거 + 안건 구조화
