# 06. PPT 초안 자동화 — 목차에서 슬라이드까지

## 학습 목표

- PPT 목차를 Copilot으로 30초에 생성하는 법 익히기
- 슬라이드별 핵심 내용 + 발표자 노트 초안 만들기
- Markdown으로 만든 초안을 파워포인트로 옮기는 흐름 이해
- 임원 보고용 1장 요약 슬라이드 작성 패턴 습득

**예상 소요**: 60분 (실습 포함)

---

## 6.1 PPT 초안이 왜 막히는가

PPT를 만들 때 가장 시간이 걸리는 구간은 디자인이 아닙니다. **목차를 잡는 것**과 **각 슬라이드에 무슨 말을 넣을지 생각하는 것**입니다.

전형적인 흐름을 보면:

1. 빈 슬라이드를 열고 한참 응시 — 5분
2. 목차를 대충 잡았는데 이게 맞는 흐름인지 불안 — 5분
3. 각 슬라이드를 채우다 갑자기 막힘 — 10분
4. "1장에 이걸 다 넣을 수 있나?" 레이아웃 고민 — 10분
5. 발표자 노트는 시간 없어서 생략 → 발표 당일 머리 하얗게

Copilot은 이 과정 중 1~4단계를 대신합니다. 여러분은 내용을 확인하고 파워포인트에 옮기기만 하면 됩니다.

---

## 6.2 PPT 만들기 3단계 흐름

```
[단계 1] 목차(Outline) 생성
  → 주제/청중/시간 입력 → Copilot이 슬라이드 목록 + 요약 생성

[단계 2] 슬라이드별 초안 생성
  → 각 슬라이드 제목으로 Copilot에게 내용 요청

[단계 3] 파워포인트로 옮기기
  → Markdown 초안을 PPT에 복사붙여넣기 또는 Outline 기능 활용
```

---

## 6.3 단계 1 — 목차 생성

### 기본 프롬프트

```
아래 조건에 맞는 발표 PPT 목차 작성.

주제: [발표 주제]
발표 시간: [N분]
청중: [누구에게]
목적: [보고 / 교육 / 제안 / 공유 중 택1]
총 슬라이드: [N장] 내외

각 슬라이드에 포함:
- 슬라이드 번호 + 제목
- 핵심 내용 2~3줄 (불릿 포인트)
- 예상 발표 시간 (분)

표지 슬라이드와 마무리 슬라이드 포함.
```

### 실제 예시 — 8월 워크숍 결과 보고 (20분 발표)

```
PPT 목차 작성.

주제: 2026년 8월 임직원 워크숍 결과 보고
발표 시간: 20분
청중: 임원 및 팀장급 전체
목적: 워크숍 결과 보고 및 개선 사항 제안
총 슬라이드: 12~15장

각 슬라이드:
- 번호 + 제목
- 핵심 내용 2~3불릿
- 예상 발표 시간

포함 섹션:
1. 개요 (목적/일정/참석 인원)
2. 프로그램 요약
3. 참가자 만족도 결과
4. 주요 성과 및 피드백
5. 개선 제안
6. 내년 방향성
표지 + Q&A + 감사 슬라이드 포함.
```

**Copilot 결과 예시**:

```markdown
## 슬라이드 목차

| # | 제목 | 핵심 내용 | 예상 시간 |
|---|------|-----------|----------|
| 1 | 표지 | 제목, 발표자, 날짜 | 1분 |
| 2 | 목차 | 발표 흐름 안내 | 1분 |
| 3 | 워크숍 개요 | 일정/장소/참석 인원 30명 | 2분 |
| 4 | 프로그램 구성 | 타임라인, 팀빌딩/강의/레크리에이션 | 2분 |
| 5 | 참가자 만족도 | 설문 결과 (평균 4.2/5.0), 긍정 비율 87% | 2분 |
| 6 | 만족도 상세 | 항목별 점수 차트, 상위/하위 3개 항목 | 2분 |
| 7 | 주요 긍정 피드백 | 인용 3~5개, 공통 키워드 | 2분 |
| 8 | 개선 요청 사항 | 상위 3개 개선점, 빈도수 표 | 2분 |
| 9 | 운영상 개선 제안 | 시간/이동/숙소 측면 구체적 제안 | 2분 |
| 10 | 비용 결산 | 예산 대비 실적, 항목별 내역 | 2분 |
| 11 | 내년 방향성 | 주기, 규모, 형식 제안 | 1분 |
| 12 | Q&A | 질의응답 | 2분 |
| 13 | 감사 | 감사 인사 + 연락처 | 1분 |
```

## 6.4 단계 2 — 슬라이드별 초안 생성

목차가 잡히면 각 슬라이드의 상세 내용을 만듭니다. 모든 슬라이드를 한 번에 요청할 수도 있고, 중요한 슬라이드만 따로 요청할 수도 있습니다.

### 한 번에 요청 (중간 이하 분량 발표)

```
위 목차에서 슬라이드 3번부터 8번까지 각각의 상세 내용 초안 작성.

각 슬라이드에 포함:
- 슬라이드 제목 (## 로 표시)
- 불릿 포인트 3~4개 (핵심 내용만, 각 항목 10단어 이내)
- 발표자 노트 3~4문장 (청중에게 실제 말할 스크립트)

수치는 [N%], [N명] 형식 플레이스홀더로 표시.
```

### 특정 슬라이드만 상세 요청

```
아래 슬라이드 내용 초안 작성.

슬라이드 제목: 참가자 만족도
핵심 메시지: 이번 워크숍은 참가자의 87%가 만족했으며 특히 팀빌딩 활동이 가장 높은 평가를 받았다.

내용 형식: 수치 중심 불릿 3개 + 핵심 수치 강조 (크게 표시 안내)
발표자 노트: 이 슬라이드에서 말할 스크립트 3문장 (자연스러운 말투로)

수치 플레이스홀더: [설문 응답률], [평균 만족도], [팀빌딩 점수]
```

**Copilot 결과 예시**:

```markdown
## 슬라이드 5 — 참가자 만족도

### 슬라이드 내용

- 전체 만족도: **[평균 만족도]/5.0** (설문 응답률 [설문 응답률]%)
- 워크숍 재참석 의향: 참가자 [N]% 긍정 응답
- 가장 높은 평가 항목: 팀빌딩 활동 (**[팀빌딩 점수]/5.0**)

### 발표자 노트

이번 워크숍의 전체 만족도는 [평균 만족도]점으로 지난 행사 대비 0.3점 상승했습니다. 특히 팀빌딩 게임 프로그램에 대한 반응이 매우 좋았는데, 부서 간 소통 기회를 원했던 직원들의 니즈와 잘 맞았던 것으로 보입니다. 다음 슬라이드에서 항목별 상세 점수를 함께 보시겠습니다.
```

## 6.5 발표자 노트 전용 생성

슬라이드 내용은 있는데 발표자 노트가 없을 때, 슬라이드 내용을 붙여넣고 노트만 따로 요청합니다.

```
아래 슬라이드 내용을 바탕으로 발표자 노트(스크립트)만 작성.

조건:
- 발표 시간: 약 2분
- 자연스럽고 구어체로 (너무 딱딱하지 않게)
- 슬라이드의 수치를 언급하는 방식으로
- 청중 인터랙션 포인트 1개 포함 (질문이나 공감 유도)

[--- 슬라이드 내용 ---]
- 전체 만족도: 4.2/5.0 (응답률 92%)
- 팀빌딩 활동 가장 높은 평가: 4.6/5.0
- 개선 필요: 식사 시간 부족 (응답자 43% 언급)
[--- 끝 ---]
```

## 6.6 임원 보고용 1장 요약 슬라이드

긴 보고서나 발표를 임원에게 1장으로 요약해야 할 때 씁니다.

**프롬프트**:

```
아래 보고 내용을 임원 보고용 요약 슬라이드 1장으로 정리.

레이아웃 (텍스트로 표현):
┌────────────────────────────────────────────────┐
│ 핵심 메시지 1줄 (굵게, 가장 크게)              │
├──────────────┬─────────────────────────────────┤
│ 주요 수치    │ 시사점 / 권고 사항               │
│ (3개 크게)   │ (불릿 3개)                       │
├──────────────┴─────────────────────────────────┤
│ 다음 단계 / 필요한 결정 1줄                     │
└────────────────────────────────────────────────┘

내용:
[보고 내용 요약 붙여넣기]
```

**Copilot 결과 예시**:

```markdown
## 임원 보고용 요약 슬라이드

### 핵심 메시지
**이번 워크숍에서 직원 87%가 만족했으며 팀 결속력 강화에 기여했습니다.**

---

### 주요 수치

| 지표 | 결과 |
|------|------|
| 전체 만족도 | **4.2 / 5.0** |
| 재참석 의향 | **87%** |
| 팀빌딩 점수 | **4.6 / 5.0** |

### 시사점 및 권고 사항

- 팀빌딩 중심 프로그램이 참가자 반응 긍정적 → 내년도 유지 권고
- 식사 시간 부족(43% 지적) → 일정 30분 조정 필요
- 비용 집행률 94% — 예산 범위 내 운영 성공

---

### 다음 단계

**내년 워크숍 예산 및 일정 확정을 위해 8월 내 임원 승인 요청**
```

## 6.7 Markdown → 파워포인트로 옮기기

Copilot이 만든 Markdown 초안을 PowerPoint에 넣는 방법입니다.

### 방법 1. 직접 복사 붙여넣기 (간단)

1. Copilot 결과에서 각 슬라이드 내용을 복사합니다.
2. PowerPoint에서 해당 슬라이드를 클릭합니다.
3. 제목 텍스트 박스에 제목 붙여넣기, 내용 박스에 불릿 내용 붙여넣기.
4. 발표자 노트 영역에 발표자 노트 붙여넣기.

작업 시간: 슬라이드 1장당 약 1분

### 방법 2. PowerPoint 개요 뷰 활용 (빠름)

1. PowerPoint 열기 > **보기** > **개요 보기**
2. 개요 뷰에서 제목과 내용을 직접 타이핑하거나 붙여넣기
3. 각 슬라이드의 계층 구조가 자동으로 반영됨
4. 나중에 **보통 보기**로 돌아와서 디자인 적용

### 방법 3. Google Slides 활용 (협업 시)

Google Slides를 쓴다면 유사하게:
1. 새 프레젠테이션 > **편집** > **찾기 및 바꾸기** 활용
2. 또는 각 슬라이드에 직접 붙여넣기

## 6.8 PPT 관련 추가 프롬프트

### 슬라이드 제목만 줄줄이 개선

```
아래 슬라이드 제목들을 더 임팩트 있게 개선해줘.
각 제목은 8단어 이내, 청중의 관심을 끌 수 있게.

원본:
1. 워크숍 개요
2. 참가자 현황
3. 만족도 조사 결과
4. 개선 사항
5. 결론
```

### 차트/표 설명 추가

```
아래 데이터를 슬라이드에 넣을 표로 정리하고,
이 표를 보면서 말할 1~2문장 설명도 추가해줘.

데이터:
팀빌딩: 4.6점 / 식사: 3.2점 / 숙소: 4.0점 / 강사: 4.3점 / 전반적 운영: 4.1점
```

### 발표 오프닝 스크립트

```
아래 발표의 오프닝 1~2분 스크립트 작성.

발표 주제: 8월 임직원 워크숍 결과 보고
청중: 임원 및 팀장
목적: 결과 공유 + 내년 워크숍 승인 요청

오프닝에 포함:
- 감사 인사 (간결하게)
- 오늘 발표 목적 1줄
- 발표 구성 안내 (목차 간략히)
- 청중 공감 유도 문장 1개
톤: 자신감 있고 친근하게
```

## 실습 — 20분 발표 PPT 목차 + 슬라이드 초안 만들기

### 실습 주제 (택1)

아래 중 **여러분 업무에 가장 가까운 주제**를 고르세요. 또는 실제 곧 있을 발표 주제로 대체하세요.

| 주제 | 대상 청중 | 발표 목적 |
|------|----------|----------|
| A. 하반기 사무실 이전 계획 | 전직원 | 정보 공유 + 협조 요청 |
| B. 신입직원 온보딩 개선 제안 | 팀장급 | 제안 승인 요청 |
| C. 연간 총무 업무 결산 보고 | 임원 | 결과 보고 |
| D. 다음 분기 부서 일정 안내 | 팀 전체 | 일정 공유 |

### 실습 단계

**Step 1.** 주제를 고르고 목차 생성 프롬프트를 씁니다 (6.3절 참고).

**Step 2.** 목차 결과를 확인하면서 필요한 슬라이드를 추가/제거합니다.

```
위 목차에서 [슬라이드명]은 빼고, [새 내용]에 대한 슬라이드를 [위치]에 추가해줘.
```

**Step 3.** 가장 중요한 슬라이드 2~3개를 골라 상세 초안을 요청합니다.

**Step 4.** 발표자 노트를 2개 슬라이드에 대해 만들어봅니다.

**Step 5.** 임원 보고용 1장 요약 슬라이드를 만들어봅니다.

**Step 6.** 실제 PowerPoint를 열어 슬라이드 2~3개에 내용을 붙여넣어봅니다.

### 완성 기준

- [ ] 10~15장 분량의 목차가 완성됐나?
- [ ] 목차의 흐름이 자연스러운가? (개요 → 본론 → 결론)
- [ ] 중요 슬라이드 2~3개의 내용 초안이 있나?
- [ ] 발표자 노트가 최소 2개 이상 만들어졌나?
- [ ] 임원 요약 슬라이드 1장이 완성됐나?

---

## 핵심 포인트

1. **PPT 막힘의 원인은 목차** — 목차만 Copilot에 맡겨도 절반이 해결된다
2. **프롬프트에 청중·목적·시간을 명시** — 그래야 슬라이드 수와 깊이가 맞게 나온다
3. **발표자 노트는 구어체로 요청** — "자연스럽게, 너무 딱딱하지 않게" 추가
4. **수치는 플레이스홀더로 받고 실제 데이터로 교체** — Copilot이 수치를 지어내지 않도록
5. **Markdown → PPT 복사는 3분이면 된다** — 디자인은 회사 템플릿을 쓰면 됨
