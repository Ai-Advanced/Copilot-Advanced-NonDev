# 01. 데이터 분析가의 하루를 바꾸는 Copilot 15가지 활용

## 학습 목표

- Copilot이 데이터 분析가의 어떤 업무를 어떻게 바꾸는지 15개 시나리오로 파악
- Before/After 비교 3개로 시간 절감 규모를 실감
- 이 과정 2일 동안 무엇을 만들게 되는지 전체 그림 파악

**예상 소요**: 30분 (실습 포함)

---

## 1.1 데이터 분析가의 하루: 솔직한 진단

분析가의 하루를 시간 단위로 분해하면 이렇습니다.

```
오전 9:00  어제 데이터 확인 → 대시보드 숫자가 이상함
오전 9:30  원인 찾는 SQL 작성 → 첫 번째 시도 실패
오전 10:00 스택오버플로우 검색, Window Function 다시 찾아봄
오전 10:45 쿼리 겨우 완성 → 결과 나옴
오전 11:00 엑셀에서 피벗 다시 만들기 (SQL 결과 후처리)
오후 12:00 점심

오후 1:00  이탈률 리포트 요청 → 새 SQL 작성 시작
오후 2:30  리포트 초안 작성 → 숫자 나열에 가까운 문서
오후 3:30  대시보드 스펙 문서 업데이트 (어디서부터 시작해야 하지?)
오후 5:00  슬랙에서 "이 숫자 왜 이래요?" 문의 대응
오후 6:00  퇴근... 못 했음
```

**문제의 본질**: 시간의 60~70%가 "분析을 위한 준비"에 사용됩니다.
실제 분析과 인사이트 도출에는 30%도 안 쓰입니다.

Copilot은 "준비" 시간을 절반 이하로 줄입니다.

---

## 1.2 15가지 활용 시나리오

### 카테고리 A. SQL 작성 및 최적화

**시나리오 1. 복잡한 집계 SQL 즉시 생성**

분析가가 SQL에서 가장 시간을 쓰는 작업: Window Function, CTE, 복잡한 서브쿼리.
Copilot에게 의도만 설명하면 뼈대를 즉시 생성합니다.

```
프롬프트:
"PostgreSQL. 월별 신규 구독자 수와 해지자 수를 동시에 집계.
테이블: subscriptions(user_id, event_type, event_date)
event_type: 'subscribe' 또는 'cancel'
결과 컬럼: year_month, new_subs, churned, net_change"
```

→ 30초 안에 완성. 직접 쓰면 10~15분.

**시나리오 2. 기존 쿼리 설명 요청**

전임자가 남긴 복잡한 쿼리를 이해해야 할 때:

```
프롬프트:
"다음 SQL 쿼리를 비개발자도 이해할 수 있게 한국어로 설명해줘.
각 WITH 절이 하는 일, 최종 SELECT의 의미, 결과 형태.
[쿼리 붙여넣기]"
```

**시나리오 3. 쿼리 최적화 제안**

45초 걸리던 쿼리를 개선하고 싶을 때:

```
프롬프트:
"다음 쿼리가 5억 행 테이블에서 느립니다. PostgreSQL 기준 최적화 방안 3가지 제안.
인덱스 추가, 서브쿼리 → CTE 변환, JOIN 순서 관점에서.
[쿼리 붙여넣기]"
```

**시나리오 4. 방언 변환**

회사에서 쓰는 DB가 BigQuery로 바뀌었을 때:

```
프롬프트:
"다음 PostgreSQL 쿼리를 BigQuery Standard SQL로 변환.
DATE_TRUNC 차이, GENERATE_SERIES → GENERATE_DATE_ARRAY 변환 포함.
[쿼리 붙여넣기]"
```

---

### 카테고리 B. 데이터 클리닝 및 탐색

**시나리오 5. 데이터 품질 오디팅 SQL**

새 데이터를 받았을 때 첫 번째 해야 할 일: 품질 파악.

```
프롬프트:
"다음 테이블의 데이터 품질 오디팅 SQL 작성 (PostgreSQL).
컬럼별 NULL 비율, 중복 행 수, 숫자형 MIN/MAX/AVG, 날짜 범위.
테이블: raw_events(user_id BIGINT, event_name VARCHAR, event_date DATE, amount NUMERIC)"
```

**시나리오 6. 지저분한 CSV 클리닝 코드**

```
프롬프트:
"pandas로 raw_data.csv를 클리닝하는 Python 코드.
작업: 헤더 소문자화, 날짜 컬럼 datetime 변환, 금액 컬럼 쉼표 제거 후 float,
결측치 현황 출력, 중복 user_id 제거 (최신 행 유지).
SettingWithCopyWarning 없이."
```

**시나리오 7. 이상치 탐지**

갑자기 MRR이 2배로 튀었을 때 원인 탐색:

```
프롬프트:
"payments.amount 컬럼에서 IQR 방식으로 이상치를 탐지하는 SQL (PostgreSQL).
이상치 행 수, 비율, 샘플 5개 출력."
```

---

### 카테고리 C. 지표 계산 및 分析

**시나리오 8. 코호트 리텐션 분析**

월별 코호트 리텐션은 분析가가 가장 자주 작성하는 복잡한 SQL 중 하나입니다.
Copilot 없이는 30~60분, Copilot과 함께하면 5~10분.

**시나리오 9. A/B 테스트 결과 집계 + 통계 검정**

전환율 비교에서 p-value까지 한 번에:

```
프롬프트:
"A/B 테스트 전환율 비교. Python scipy 사용.
A그룹: 전환 2,254 / 전체 12,340
B그룹: 전환 2,668 / 전체 12,289
proportions_ztest로 검정 + 95% 신뢰구간 + 한국어 해석."
```

**시나리오 10. RFM 세그먼테이션**

고객 세그먼트를 SQL 하나로:

```
프롬프트:
"PostgreSQL. payments(user_id, amount, paid_at) 기준 RFM 분析.
R/F/M 각각 NTILE(5)로 스코어링.
세그먼트: Champions(13~15)/Loyal(10~12)/At Risk(6~9)/Lost(3~5).
세그먼트별 사용자 수, 평균 금액 출력."
```

---

### 카테고리 D. 시각화 코드 생성

**시나리오 11. 차트 코드 즉시 생성**

분析가가 Python 시각화에서 막히는 이유는 문법이 아니라 "어떤 함수를 어떤 순서로 쓰나"입니다.
Copilot이 전체 코드를 생성하면 여러분은 데이터만 교체합니다.

```
프롬프트:
"seaborn으로 코호트 리텐션 히트맵.
입력: retention_df (행=코호트 월, 열=Month 0~12, 값=비율 0~1).
색상: 초록 계열, 셀 안에 % 값 표시, 그림 크기 (14, 8)."
```

**시나리오 12. 차트 스타일 개선**

기존 차트를 발표용으로 업그레이드:

```
프롬프트:
"다음 matplotlib 코드를 개선해줘.
- 폰트 크기 제목 16, 축 레이블 12
- 배경을 흰색으로
- 격자선은 연한 회색
- 범례 위치 오른쪽 상단
[기존 코드 붙여넣기]"
```

---

### 카테고리 E. 문서화 및 스토리텔링

**시나리오 13. 인사이트 문장 자동화**

숫자를 보고 무엇을 써야 할지 막막할 때:

```
프롬프트:
"다음 분析 결과를 임원 보고용 인사이트 3문장으로 작성.
- 3월 신규 가입 +12% (전월 대비)
- 이탈률 8.3% (전월 7.1%에서 악화)
- 30일 리텐션 62% (업계 평균 58% 상회)
형식: 긍정 신호 / 위험 신호 / 권고 액션. 수치 반드시 포함. 애매한 표현 금지."
```

**시나리오 14. 대시보드 스펙 문서 초안**

BI 도구용 스펙 문서를 처음부터 쓰는 데 1~2시간, Copilot과 함께하면 15분:

```
프롬프트:
"구독 서비스 운영 현황 대시보드 스펙 문서 초안 (Tableau용).
포함 차트: KPI 카드 4개, MRR 트렌드, 코호트 리텐션 히트맵, 퍼널 차트.
각 차트별: 차트 유형, 데이터 소스, 집계 방식, 필터, 업데이트 주기."
```

**시나리오 15. 지표 정의서 작성**

지표 정의가 팀마다 달라서 생기는 혼란을 방지:

```
프롬프트:
"다음 6개 지표의 공식 정의서를 Markdown 테이블로.
MRR, ARR, 이탈률, NRR, LTV, CAC.
컬럼: 지표명 | 정의 | 계산 공식 | 단위 | 측정 주기 | 데이터 소스"
```

## 1.3 Before / After: 시간 절감 3가지 사례

### Case 1. 코호트 리텐션 SQL

**Before (Copilot 없이)**

1. "월별 코호트 리텐션 SQL" 구글 검색 (5분)
2. 블로그 예시 찾아서 복사, 내 테이블 구조에 맞게 수정 (20분)
3. 컬럼명 오류 디버깅 (10분)
4. 결과가 이상해서 로직 재검토 (15분)
5. 완성 (50분 소요)

**After (Copilot과 함께)**

1. 프롬프트 작성 + 스키마 붙여넣기 (3분)
2. 생성된 SQL 검토 + JOIN 방향 확인 (3분)
3. 실행 + 결과 확인 (2분)
4. 완성 (8분 소요, 83% 단축)

---

### Case 2. 이탈 분析 리포트

**Before**

1. 이탈 관련 SQL 3~4개 작성 (40분)
2. 결과를 엑셀에 복사해서 차트 생성 (20분)
3. 리포트 초안 작성 — 숫자 나열 수준 (30분)
4. 임원에게 전달 → "인사이트가 뭐예요?" 질문 받음 (0분)
5. 리포트 재작성 (20분)
6. 총 110분

**After**

1. 이탈 분析 SQL 프롬프트 3개 (15분)
2. Python으로 시각화 코드 생성 (10분)
3. 인사이트 문장 프롬프트로 초안 생성 후 수정 (10분)
4. 총 35분 (68% 단축)

---

### Case 3. 새 DB 테이블 파악

**Before**

1. 스키마 문서 찾기 (있으면 다행, 없으면 개발자 문의 대기) (20분)
2. 데이터 품질 파악용 쿼리 수동 작성 (15분)
3. 이상한 값 찾아서 원인 문의 (10분)
4. 총 45분+

**After**

1. `INFORMATION_SCHEMA` 또는 스키마 복사 후 프롬프트로 오디팅 SQL 생성 (5분)
2. 실행 결과로 품질 현황 즉시 파악 (5분)
3. 총 10분 (78% 단축)

## 1.4 Copilot 사용 패턴: 분析가를 위한 3가지 모드

### 모드 1. Chat 사이드바 (주력 모드)

`Ctrl+Alt+I`로 사이드바 열기. 긴 프롬프트, 복잡한 SQL, 설명 요청에 씁니다.
- 스키마 정보를 한 번 설명하면 대화가 이어지는 동안 기억합니다
- "위 쿼리에서 월별 합계도 추가해줘" 같은 후속 요청 가능

### 모드 2. Inline Chat (파일 안에서)

`.sql` 파일이나 `.py` 파일 안에서 `Ctrl+I`. 현재 파일의 맥락을 자동으로 이해합니다.
- 이미 작성된 SQL 바로 위에서 "이 쿼리에 WHERE 조건 추가" 요청
- Python 파일에서 함수 위에 커서 놓고 "이 함수 설명 주석 추가" 요청

### 모드 3. 탭 자동완성

SQL 파일에서 `--` 주석으로 의도를 쓰면 Copilot이 다음 줄을 제안합니다.

```sql
-- 월별 신규 가입자 수를 plan별로 집계
-- 테이블: subscriptions, 컬럼: user_id, plan, event_date, event_type='subscribe'
SELECT   -- Copilot이 여기서부터 자동 완성 제안
```

## 핵심 포인트

1. 분析가 업무의 60~70%는 "준비"(SQL 작성·클리닝·포맷팅). Copilot은 이 시간을 절반 이하로 줄인다
2. 15개 활용 시나리오 중 SQL(1~4), 클리닝(5~7), 지표(8~10), 시각화(11~12), 문서화(13~15)로 구분
3. Chat 사이드바(복잡한 요청) / Inline Chat(파일 내 수정) / 탭 자동완성(흐름 유지) 3개 모드
4. **스키마 먼저, 방언 명시, 검증 필수** — 이 3가지 원칙은 모든 챕터에서 반복됩니다
