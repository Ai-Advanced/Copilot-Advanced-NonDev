# 직군별 웹 결과물과 검증 레시피

[공통 배포 과정으로](README.md)

모든 직군이 같은 앱을 새로 만드는 대신 **기존 캡스톤의 산출물을 입력**으로 사용합니다.
아래 입력 데이터는 가상 데이터로 재작성합니다. 공통 절차와 배포 코드는 README 한곳에서 관리합니다.

| 직군 | 기존 결과물 → 웹 결과물 | Copilot CLI에 추가할 요구사항 | 직접 확인할 기준 |
| --- | --- | --- | --- |
| 기획 / PM | 도서 서비스 프로토타입 → 3화면 데모 | 제목 검색, 도서 상세, 현재 탭의 독서 기록. 대출·계정 기능은 제외 | 검색 1건/0건, 화면 전환, 중복 기록 방지 |
| 디자이너 | 디자인 토큰·HTML → 컴포넌트 쇼케이스 | 가상 SaaS 화면과 버튼·입력·오류 상태, 키보드 포커스 | 320px 화면, Tab 이동, 색 대비와 상태 전환 |
| 마케터 | 캠페인 카피·성과 보고서 → 랜딩 페이지 | 실제 전송 없는 신청 폼, 샘플 KPI, 광고·추적 태그 제외 | 빈 이메일 차단, 전송되지 않음을 표시, KPI 합계 |
| 영업 / CS | 파이프라인·CS 매크로 → FAQ·견적 도구 | 샘플 상품 3종, 수량별 합계, FAQ 검색. CRM 연동 제외 | 수량 0/음수 거부, 가격×수량 검산, 빈 검색 결과 |
| HR / 인사 | 가상 JD·온보딩 문서 → 채용 안내·체크리스트 | 가상 직무 안내, 일정, 현재 탭 체크리스트. 지원서 접수 제외 | 실제 지원자 정보 없음, 체크 상태와 완료 개수 일치 |
| 재무 / 회계 | 샘플 결산 산출물 → 읽기 전용 웹 보고서 | 집계한 가상 수치와 예산 대비 차이. 원장·VBA 실행 제외 | 매출-원가-판관비 검산, 예산 0일 때 비율 표시 정책 |
| 일반 오피스 | 월간 부서 운영 문서 → 업무 안내 포털 | 일정·업무별 체크리스트, 샘플 연락처. 메일 발송 제외 | 업무 필터, 완료 개수, 새로고침 시 초기화 안내 |
| 데이터 분석 | 가상 Zeta 분석 결과 → 시각화 대시보드 | 샘플 집계 데이터, 기간 필터, 분모와 단위 표시 | 필터별 합계, 비율의 분모, 데이터 없는 기간 |

## 각 직군의 캡스톤에 공통으로 붙이는 프롬프트

```text
이 폴더의 교육용 산출물을 읽고 [내 직군]의 웹 결과물을 만들어줘.
입력으로 사용할 파일: [실습용 파일만 지정]
기존 결과물에서 유지할 내용: [핵심 문구·수치·흐름]
웹에서 작동해야 하는 기능: [위 표에서 선택]
직접 확인할 기준: [위 표에서 선택]

index.html을 진입점으로 만들고 HTML/CSS/JavaScript만 사용해.
실제 개인정보·원장·고객 정보는 넣지 말고 가상 데이터 표시를 해.
원래 Python/VBA를 웹에서 실행한 것처럼 보이게 하지 마.
서버가 필요한 기능은 구현 전에 구분해서 설명해.
빈 값·잘못된 입력·작은 화면을 고려하고, 외부로 데이터를 전송하지 마.
배포 전에 결과물과 파일 목록을 함께 검토하자.
```

## 정적 보고서와 서버 앱의 구분

재무·데이터 직군의 기본 과정은 **로컬에서 검증한 가상 집계 결과를 웹으로 표현**하는 것입니다.
브라우저에서 수치를 다시 계산하는 경우 그 계산도 별도로 검산합니다.
파일 업로드·원장 가공·예약 실행·DB 연결을 요청하면 기본 범위를 넘으므로 [서버 앱 선택 심화](server-app.md)로 이동합니다.
선택 심화의 제공 예제 역시 읽기 전용 가상 보고서이며, 실제 결산 자동화 전체를 운영 서비스로 전환한 예제가 아닙니다.
